- **금융위 기업 재무정보(요약재무제표)와 기업기본정보는 2026-11-12부터 사용 중단**. 서비스에서 쓰지 않는다 (재무·업종·결산월은 DART로).
- 사용자 발언: "과제 조건은 상관없어. B로 적용해" (B = 재무와 회사 정보를 DART로 옮기는 안). 과제 조건 때문에 금융위 API를 유지할 필요는 없다.
- 이유:
  - 재무 출처가 하나가 된다 (일반 회사와 금융회사를 다른 API로 받지 않음).
  - 금융회사 재무·업종 코드·결산월 문제가 한 번에 풀린다.
  - 분기 실적 등으로 나중에 넓히기 쉽다.
  - 금융위 API는 20초 넘는 지연과 "정상 응답인데 0건"을 겪었다.
- DART만으로 전부 하지 않는 이유: DART에는 주가·시가총액이 없어 F-09와 시가총액 정렬에 주식시세정보가 필요하다.
- **검색 대상 종목은 지금처럼 KRX상장종목정보로 정하고, DART는 그 종목의 데이터를 받는 데만 쓴다.** DART 고유번호 목록에는 종목코드가 있어도 현재 상장 여부를 알 수 없는 회사(`corp_cls` E 기타)가 많다 (아래 DART 절).

### 환경변수 (API 키)

공공데이터포털은 **계정당 인증키 하나**를 발급하고, 활용신청한 모든 API에 같은 키를 쓴다. 세 API의 키가 같은 것을 확인했으므로(2026-11-03) 변수 하나로 관리한다.

| 변수명 | 값 | 용도 |
| --- | --- | --- |
| `DATA_GO_KR_SERVICE_KEY` | 공공데이터포털 마이페이지의 **일반 인증키** | KRX상장종목정보, 주식시세정보 |
| `DART_OPENAPI_KEY` | DART OpenAPI 인증키 (40자, 2026-11-12 사용자 추가) | DART 고유번호 목록·기업개황·주요계정. 요청 파라미터 이름은 `crtfc_key` |

코드에서 `requests`의 `params=`처럼 라이브러리가 URL 인코딩을 하므로, 환경변수에는 **인코딩되지 않은 형태**를 넣는다. 포털이 일반 인증키 하나만 보여주는 경우가 있어, 키에 든 문자로 판단한다.

| 키에 들어 있는 문자 | 의미 | 할 일 |
| --- | --- | --- |
| 영문과 숫자만 | 인코딩·디코딩 구분이 없음 | 그대로 넣기 |
| `+`, `/`, `=` | 디코딩 형태 | 그대로 넣기 |
| `%2B`, `%2F`, `%3D` 같은 `%` 문자 | 인코딩 형태 | `urllib.parse.unquote`로 바꾼 뒤 넣기 |

인증 오류(`SERVICE_KEY_IS_NOT_REGISTERED_ERROR`)가 나면 키가 두 번 인코딩되었는지 먼저 확인한다.

- **DART 인증키는 본인 키 하나만 쓰고 공유하지 않는다** (2026-11-16, DART 이용약관 제19조 ② 제3자 이용 금지·⑤ ID·인증키 1인 1개). GitHub Secrets·Vercel 환경변수에 넣는 키도 본인 키 하나이며, 다른 사람에게 주거나 다른 사람의 키를 받아 쓰지 않는다.

**관리 방법: `.env` 파일**

- 개인 서버(Ubuntu 24.04)에서도 같은 방식이다. 실행은 프로젝트 루트에서 한다 (2026-11-16 이전 기록).

- 프로젝트 루트에 `.env`를 만들고 아래 한 줄을 넣는다. 따옴표와 공백은 넣지 않는다.

  ```
  DATA_GO_KR_SERVICE_KEY=발급받은_디코딩_키
  ```

- `.gitignore`에 `.env`를 추가해 키가 git에 올라가지 않게 한다.
- 값을 비운 `.env.example`은 git에 올려, 어떤 변수가 필요한지 기록한다.
- Python 배치는 표준 라이브러리로 `.env`를 직접 읽는다 (`batch/common.py`). Next.js는 기본 기능으로 `.env`를 읽는다. 키는 서버(백엔드·배치)에서만 쓰고 브라우저 코드에는 넣지 않는다. Next.js에서는 `NEXT_PUBLIC_`으로 시작하는 이름을 쓰지 않는다. 이 접두어가 붙으면 브라우저에 노출된다.

### 공공 API 호출 규칙

- 모든 API는 **GET** 요청이며 파라미터는 쿼리스트링으로 보낸다.
- 공통 파라미터: `serviceKey`, `pageNo`, `numOfRows`, `resultType=json`
- 정상 응답은 `header.resultCode == "00"`. 이때 `totalCount == 0`이면 오류가 아니라 조건에 맞는 데이터가 없다는 뜻이다.
- 금융위원회 데이터는 실시간이 아니다. 기준일자 다음 영업일 오후 1시 이후에 갱신된다.

### 금융위원회_주식시세정보 (2026-11-12 연결 확인, 토론 세션이 실제 호출)

- **엔드포인트:** `https://apis.data.go.kr/1160100/GetStockSecuritiesInfoService_V2/getStockPriceInfo_V2` (응답 200, `resultCode "00"`)
  - KRX상장종목정보처럼 주소에 **`/service/`가 없다.** `/service/`를 넣으면 HTTP 400 `NO_OPENAPI_SERVICE_ERROR`.
  - V2가 아닌 예전 주소(`/service/GetStockSecuritiesInfoService/getStockPriceInfo`)는 403 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`였다 (F-09 첫 호출의 403은 이 때문으로 보임).
  - 출처: 상세기능 이름 `getStockPriceInfo_V2`와 일일 트래픽은 사용자가 포털 화면에서 붙여 준 것. 서비스 이름 부분(`GetStockSecuritiesInfoService_V2`)은 토론 세션이 후보로 넣어 200 응답으로 확인한 것이다. **포털 "활용신청 상세"의 End Point 표기와는 대조하지 않았다.** → **대조는 하지 않기로 함 (2026-11-16, 사용자 A안):** 실제 호출로 정상 응답을 확인해 충분하고, 주소가 바뀌면 호출 실패로 바로 알 수 있다.
  - 같은 서비스의 다른 상세기능(사용자 제공): 수익증권시세 `getSecuritiesPriceInfo_V2`, 신주인수권증권시세 `getPreemptiveRightSecuritiesPriceInfo_V2`, 신주인수권증서시세 `getPreemptiveRightCertificatePriceInfo_V2`. 이 프로젝트는 주식시세만 쓴다.
- **일일 트래픽: 상세기능당 10,000회** (포털 화면 기준).
- 키는 기존 `DATA_GO_KR_SERVICE_KEY` 그대로 동작한다. 공통 파라미터도 같다 (`serviceKey`, `pageNo`, `numOfRows`, `resultType=json`).

**확인한 동작**

- 조건 없이 부르면 전체 약 456만 건이 최신 날짜부터 온다. 최신 `basDt`는 `20261111`이었다 (KRX상장종목정보의 최신 `20261106`과 다를 수 있음).
- **`basDt` + `numOfRows=5000` 한 번으로 그날 전 종목 2,876건**을 받았다 (KOSPI 936, KOSDAQ 1,833, KONEX 107) → 전 종목 시세는 하루 1회 호출로 충분하다.
- `likeSrtnCd`, `likeItmsNm` 조건이 동작한다. 과거 날짜(`basDt=20251230`)도 조회된다.
- 시가총액이 비어 있거나 0인 행은 없었다.

**주의점**

- **`srtnCd`에 `A`가 붙지 않는다** (`005930`). KRX상장종목정보는 `A005930`이므로 맞출 때 `A`를 뗀다. 이 API에는 `crno`가 없어서 종목코드나 `isinCd`로 KRX 목록과 연결한다.
- **우선주가 들어 있다** (이름으로 센 것만 약 112건, 예: 삼성전자우 `005935`). KRX상장종목정보에는 우선주가 없다. KOSPI 건수 차이(936 vs 828)도 대부분 이 때문으로 보인다 (추정).
- **`mrktTotAmt`는 그 종목(보통주)만의 시가총액이다.** 삼성전자 보통주 약 1,204조, 삼성전자우 약 132조가 따로 온다. PER·PBR을 보통주 시가총액만으로 계산하면 우선주가 있는 회사는 값이 조금 낮게 나온다 → **보통주 시가총액만으로 계산하고 화면에 "보통주 시가총액 기준"이라고 적는다** (2026-11-12 결정, F-09).
- 확인 스크립트는 토론 세션 scratchpad에 있어 프로젝트에는 남지 않는다.

**KRX상장종목정보 요청변수** (포털 활용신청 상세 화면 기준, `ref/`에 저장된 페이지)

- 상세기능: `getItemInfo_V2` (종목정보), 일일 트래픽 10,000건
- 공통: `serviceKey`, `numOfRows`, `pageNo`, `resultType`(기본값 xml이므로 `json` 지정)
- 기준일자: `basDt`(일치), `beginBasDt`(이상), `endBasDt`(미만), `likeBasDt`(포함)
- 종목: `likeSrtnCd`(단축코드 포함), `isinCd`·`likeIsinCd`(ISIN), `itmsNm`(종목명 일치), `likeItmsNm`(종목명 포함)
- 법인: `crno`(법인등록번호 일치), `corpNm`·`likeCorpNm`(법인명)
- 단축코드는 "일치" 검색이 없고 "포함" 검색(`likeSrtnCd`)만 있다.

**KRX상장종목정보에서 확인한 것**

| 필드 | 의미 | 예 |
| --- | --- | --- |
| `basDt` | 기준일자 | `20261102` |
| `srtnCd` | 단축코드 (**앞에 `A`가 붙음**) | `A005930` |
| `isinCd` | ISIN코드 | `KR7005930003` |
| `mrktCtg` | 시장구분 | `KOSPI`, `KOSDAQ`, `KONEX` |
| `itmsNm` | 종목명 | `삼성전자` |
| `crno` | 법인등록번호 | `1301110006246` |
| `corpNm` | 법인명 | `삼성전자(주)` |

- **기준일자를 지정하지 않으면 모든 날짜의 기록이 섞여 온다.** 조건 없이 부르면 약 431만 건, `likeItmsNm=삼성전자`만 보내도 1,676건인데 대부분 같은 종목의 날짜별 기록이다. 반드시 `basDt`에 최신 기준일자를 넣는다.
- 결과는 최신 기준일자부터 온다. `numOfRows=1`로 한 건만 받아 최신 `basDt`를 알아낸 뒤 그 날짜로 조회한다. 2026-11-04 00시 기준 최신은 `20261102`였다 (영업일 다음 날 오후 1시 이후 갱신).
- **종목코드에 `A`가 붙어 있다** (`A005930`). 화면에는 `A`를 뗀 6자리로 보여주고, 검색도 6자리로 한다. 저장은 원본 값 그대로 하고 표시할 때만 뗀다 (제4유형 변경금지).
- **외국회사는 `crno`가 비어 있지 않고 `0000000000000`으로 온다** (예: 딥커머스, 헝셩그룹 등, ISIN이 `HK`로 시작). 0으로만 된 값을 "법인등록번호 없음"으로 판단한다.
- 시장구분은 `KOSPI`, `KOSDAQ`, **`KONEX`** 세 가지다 (아래 3차 실행 결과).
- 이름에 "스팩"이 들어간 기업인수목적회사가 섞여 있다 (예: 디비금융제14호스팩). 실적 그래프의 의미가 없으므로 **검색 대상에서 제외한다** (2026-11-09 결정).
- **우선주는 이 API에 없다.** 보통주만 온다 (아래 3차 실행 결과).
- **업종 정보가 없다.** 그래서 금융회사 등을 이 목록만으로 골라낼 수 없다.
- 단축코드 "포함" 검색(`likeSrtnCd`)을 기준일자 없이 부르면 시간 초과가 났다. 서비스에서는 종목 목록을 미리 저장해 두고 검색하므로 실제 영향은 없다.

- 기준일자 `20261106` 전체 종목: **2,764건** (`numOfRows=5000` 한 번에 받음, `basDt` 중복 없음)

### 금융감독원 DART OpenAPI (2026-11-12 연결 확인, 토론 세션이 실제 호출)

> **재무·업종·결산월의 주 출처** (2026-11-12 결정, 위 "데이터 출처 구조"). 재무는 단일회사 주요계정, 업종·결산월은 기업개황에서 받는다. 주소는 토론 세션이 기억하던 것을 실제 응답(HTTP 200, `status` "000 정상")으로 확인했고, **DART 개발가이드와는 대조하지 않았다.** 확인 스크립트는 토론 세션 scratchpad에 있어 프로젝트에는 없다.

**키**
- 프로젝트 루트 `.env`의 `DART_OPENAPI_KEY` (사용자가 추가, 40자). 공공데이터포털 키와 같은 보안 규칙을 따른다 (`.env`를 열지 않음, 변수 이름으로만 불러옴, 서버에서만 사용).
- 요청 파라미터 이름은 `crtfc_key`다. URL을 출력할 때 값을 `***`로 가린다.

**확인한 상세기능 3개**

| 상세기능 | 주소 | 확인 내용 |
| --- | --- | --- |
| 고유번호 목록 | `https://opendart.fss.or.kr/api/corpCode.xml` | zip 안에 xml 1개. 전체 119,989건, 종목코드(`stock_code`)가 있는 회사 4,015건. 필드: `corp_code`, `corp_name`, `corp_eng_name`, `stock_code`, `modify_date` |
| 기업개황 | `https://opendart.fss.or.kr/api/company.json?corp_code=` | 필드 19개: `acc_mt`, `adres`, `bizr_no`, `ceo_nm`, `corp_cls`, `corp_code`, `corp_name`, `corp_name_eng`, `est_dt`, `fax_no`, `hm_url`, `induty_code`, `ir_url`, `jurir_no`, `phn_no`, `stock_code`, `stock_name`, `status`, `message` |
| 단일회사 주요계정 | `https://opendart.fss.or.kr/api/fnlttSinglAcnt.json?corp_code=&bsns_year=&reprt_code=` | `reprt_code`: 11011 사업보고서, 11013 1분기, 11012 반기, 11014 3분기. 행 필드: `account_nm`, `sj_div`, `sj_nm`, `fs_div`(CFS 연결 / OFS 별도), `fs_nm`, `thstrm_amount`(당기), `frmtrm_amount`(전기), `bfefrmtrm_amount`(전전기), 각 `_dt`·`_nm`, `thstrm_add_amount`(분기 보고서의 누적), `currency`, `ord`, `rcept_no`, `bsns_year`, `reprt_code`, `corp_code`, `stock_code` |

**확인한 사실**
- **DART는 `corp_code`(8자리 고유번호)로 조회한다.** 종목코드 → `corp_code`는 `corpCode.xml`로 찾는다 (삼성전자 `005930` → `00126380`).
- **기업개황의 `jurir_no`가 법인등록번호다.** 삼성전자 `1301110006246`으로 금융위 API의 `crno`와 일치 → 두 API를 법인등록번호로 연결할 수 있다.
- **기업개황에 업종 코드(`induty_code`)와 결산월(`acc_mt`)이 있다.** 삼성전자 264, KB금융 64992, 기업은행 64121, 삼성생명 65110, 네 곳 모두 `acc_mt` 12. 자릿수가 3자리·5자리로 섞여 있다. 한국표준산업분류 코드로 보이지만(추정) 분류표와 대조하지 않았다.
- **사업보고서 1회 호출에 3개년(당기·전기·전전기)이 온다.** 삼성전자 2025 사업보고서 연결: 매출액 333.6조 / 300.9조 / 258.9조, 영업이익 43.6조 / 32.7조 / 6.57조. 2023년 영업이익 6,566,976,000,000원은 금융위 API 연결 값(+6.57조)과 맞는다.
- **분기 값이 온다.** 삼성전자 2025: 1분기 매출 79.1조, 반기 보고서 당기(2분기 석 달) 74.6조·누적 153.7조, 3분기 보고서 당기 86.1조·누적 239.8조. **4분기만의 값은 따로 없고** 사업보고서 연간 값에서 3분기 누적을 빼야 한다.
- **금융회사 데이터가 있다.** KB금융·기업은행·삼성생명 2025 사업보고서가 모두 정상으로 왔다 (각 34~37행). 자산총계·부채총계·자본총계·자본금·영업이익(손실)·당기순이익(손실)·법인세차감전 순이익이 있다. **매출액 계정은 없고** 대신 이자수익·순이자손익·순수수료손익 등이 온다. (금융위 기업 재무정보는 이 회사들이 0건이었다.)
- 2015 사업연도도 조회된다 (삼성전자 26행).
- **주의:**
