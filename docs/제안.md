# 추가 기능 제안 (N-1 ~ N-8)

> 2026-11-13 기능 설계 세션이 정리한 추가 기능 제안이다. **아직 채택 전 단계**이며, 확정된 설계는 `docs/개발기능.md`를 따른다.
> 이 문서의 후보는 `docs/개발기능.md`의 기능 목록·기능 설계·결정 기록에 들어가지 않았고 F-xx 번호도 없다. 임시 번호 N-1 ~ N-8을 쓴다. (예외: 채택된 N-6 → F-14, N-4 → F-15, N-3 → F-16)
> 문서 안 화면 문구 예시는 프로젝트 원칙대로 반말로 쓰고, 권유·평가 표현은 넣지 않는다.

## 0. 배경

- **대상:** 이제 막 투자를 시작하려는 개인 초보 투자자.
- 지금 설계(F-01 ~ F-13)는 "회사를 이미 골랐고 재무 용어를 대충 아는 사람"에게 맞춰져 있다. 처음 온 사람은 그 앞(무엇을 볼지, 이 말이 무슨 뜻인지)과 그 뒤(본 것을 어떻게 정리할지)에서 막힌다. 그래서 후보를 그 두 곳에 모았다.
- `docs/개발기능.md` 아이디어 보관함에 이미 있는 아이디어(종목 2~3개 비교, 감사의견 표시, 기본 정보 카드, 최근 검색)는 겹쳐서 뺐다.

## 2. 장벽별 제안

### 장벽 A. 용어와 숫자가 안 읽힌다

#### N-1. 100원으로 보기

- **문제:** "매출 258조, 영업이익 6.5조"라고 하면 크기가 잘 와닿지 않는다.
- **기능:** 최근 연도 실적을 매출 100원 기준으로 바꿔 한 줄 그림으로 보여준다. 연도를 바꾸면 3년 치를 볼 수 있다.
  ```
  100원어치를 팔면
  [ 매출 100원 ] → [ 영업이익 8원 ] → [ 순이익 5원 ]
  ```
- **데이터:** DART 주요계정. 이미 수집하는 값이라 추가 호출이 없다.
- **주의:** 금융회사는 매출액 계정이 없어서 표시하지 않는다.
- **붙는 곳:** F-02 · **난이도:** 낮음

#### N-2. 용어 사전 + 이 회사 숫자로 풀이

- **문제:** 툴팁은 한 줄이라서 "부채비율 87%"가 무슨 뜻인지 끝까지 설명하지 못한다.
- **기능:** 용어를 누르면 옆에 풀이가 열린다. 풀이에는 뜻, 계산식, 지금 보는 회사의 숫자를 넣은 계산이 들어간다 (예: "부채 87억 ÷ 자본 100억 = 87%"). 용어만 모은 사전 페이지도 둔다.
- **데이터:** 풀이는 고정 텍스트, 숫자는 수집한 값을 쓴다. 보관함의 "용어 쉬운 설명"을 화면 기능으로 키운 것이다.
- **주의:** "낮을수록 좋아" 같은 평가는 넣지 않고 계산의 의미만 적는다.
- **붙는 곳:** 전체 · **난이도:** 낮음 (문구 작성 필요)

### 장벽 B. 어디서부터 봐야 할지 모른다

#### N-3. 처음 읽는 순서 안내 — **채택 → F-16 (2026-11-14)**

- **채택:** 사용자가 기능 설계 세션과 질문 8개로 설계를 마치고 F-16 처음 읽는 순서 안내로 채택했다. **설계는 `docs/개발기능.md` F-16.** 아래는 처음 제안 원문이다.
- **확정 요약:** 종목 화면에서 화면을 어둡게 하고 영역을 하나씩 밝히는 짚어 주는 투어. 원문 4단계에 배당을 더한 5단계(얼마나 파나 → 얼마나 남기나 → 빚은 얼마나 → 주가는 이익의 몇 배 → 배당은 주나), 금융회사는 있는 영역만 3단계. 첫 방문 알림 띠 + 고정 "읽는 순서" 버튼. 말풍선은 읽는 법만 적은 고정 문구(회사 숫자 없음). 데이터·추가 호출 없음, 브라우저에 값 하나만 저장.
- **문제:** 종목 화면에 그래프, 눈금, 문장, PER이 한꺼번에 나와서 무엇부터 읽을지 모른다.
- **기능:** 첫 방문 때 "읽는 순서 볼래?" 버튼을 띄우고, 4단계로 화면을 짚어 준다. 건너뛸 수 있고 다시 볼 수 있다.
  1. 얼마나 파나
  2. 얼마나 남기나
  3. 빚은 얼마나
  4. 주가는 이익의 몇 배
- **데이터:** 없음. 안내를 봤는지만 브라우저에 저장한다.
- **붙는 곳:** 종목 화면 · **난이도:** 낮음

#### N-4. 업종으로 둘러보기 — **채택 → F-15 (2026-11-14)**

- **채택:** 사용자가 기능 설계 세션과 질문 7개로 설계를 마치고 F-15 업종으로 둘러보기로 채택했다. **설계는 `docs/개발기능.md` F-15.** 아래는 처음 제안 원문이다.
- **확정 요약:** 상단 메뉴 세 번째 "업종으로 둘러보기". 대분류를 누르면 중분류가 펼쳐지고(정식 이름 + 회사 수), 중분류를 누르면 회사 목록(종목명·종목코드·시장 + 시가총액, 가나다순·시가총액순)이 나온다. 금융회사도 넣는다. F-08 "같은 업종 회사 보기" 목록과는 따로 두고 서로 잇는다. 추가 API 호출 없음.
- **문제:** 검색창은 회사 이름을 알아야 쓸 수 있는데, 초보자가 아는 상장사는 몇 개뿐이다.
- **기능:** 업종(중분류) 목록을 고르면 그 업종의 회사 목록이 나온다. 정렬은 가나다순과 시가총액순만 둔다.
- **데이터:** DART 업종 코드와 주식시세정보 시가총액. F-08·F-09와 같은 데이터다.
- **주의:** "인기 종목", "많이 본 종목"은 추천으로 읽히므로 넣지 않는다. 중분류 이름표 확보(기존 할 일)가 먼저 되어야 한다.
- **붙는 곳:** F-01·F-08 · **난이도:** 중간

### 장벽 C. 숫자가 언제 것인지, 원문이 어디 있는지 모른다

#### N-5. 숫자의 기준 시점과 원문 링크

- **문제:** 초보자는 화면 숫자를 "지금 상태"로 읽는다. 하지만 사업보고서 숫자는 길게는 1년 넘게 지난 값이다.
- **기능:** 종목 화면 위에 아래 같은 한 줄을 띄우고, "DART에서 원문 보기" 링크를 단다.
  - "이 실적은 2025년 사업보고서 기준이야. 다음 사업보고서는 2027년 3월쯤 나와"
- **데이터:** 결산월(`acc_mt`)과 사업보고서 제출 기한(사업연도 종료 후 90일)으로 계산한다.
- **확인된 사실 (2026-11-13):**
  - 배당 API(`alotMatter`) 응답에 접수번호 `rcept_no`가 온다.
  - DART 개발가이드에 원문 주소 형식 `https://dart.fss.or.kr/dsaf001/main.do?rcpNo=접수번호`가 적혀 있다.
  - 주요계정(`fnlttSinglAcnt`) 응답에도 `rcept_no`가 오는지는 아직 확인하지 않았다.
- **붙는 곳:** 종목 화면 · **난이도:** 낮음

#### N-6. 배당 정보 — **채택 → F-14 (2026-11-13)**

- **채택:** 사용자가 기능 설계 세션과 질문 11개로 설계를 마치고 F-14 배당 정보로 채택했다. **설계는 `docs/개발기능.md` F-14**, DART 배당 API 조사 기록은 같은 문서 공통 사항 DART 절 "배당에 관한 사항"에 있다.
- **처음 문제:** 초보자가 가장 먼저 묻는 것 중 하나가 "배당 주는 회사야?"인데 설계에 없었다.
- **확정 요약:** 종목 화면의 별도 "배당" 카드에 최근 3년 보통주 주당 현금배당금·현금배당수익률을 표로 보여준다 (배당성향 제외). 무배당도 카드를 표시한다. 스크리너에 "배당" 묶음과 필터 20번 "3년 내내 현금배당한 회사"를 추가한다. 수집은 사업보고서 3개년·종목당 1회 (처음 수집 약 10,300회).

### 장벽 D. 본 것을 정리하고 스스로 판단하는 방법이 없다

#### N-7. 내 확인표

- **문제:** 숫자를 봐도 무엇을 확인했는지 남지 않는다. 그래서 결국 남의 말이나 느낌으로 결정한다.
- **기능:** 종목마다 확인표를 두고 사용자가 직접 체크한다. 항목은 사실 확인 질문만 넣는다.
  ```
  □ 3년 매출 흐름을 봤어
  □ 영업이익이 흑자인지 적자인지 봤어
  □ 부채비율을 봤어
  □ 같은 업종 가운데 값과 견줘 봤어
  □ 이 숫자가 언제 기준인지 확인했어
  ```
- **데이터:** 로그인 전에는 브라우저에, 로그인 뒤에는 F-12 추적 종목에 저장한다.
- **주의:** 체크 개수로 점수나 "준비 완료" 같은 말을 만들지 않는다. 서비스 이름(투자판단은본인에게)과 가장 잘 맞는 기능이다.
- **붙는 곳:** 종목 화면·F-12 · **난이도:** 중간

#### N-8. 추적 종목 메모 + 등록 때와 지금

- **문제:** 추적 종목에 왜 넣었는지 잊고, 새 실적이 나와도 무엇이 달라졌는지 모른다.
- **기능:** 등록할 때 한 줄 메모를 적고, 그때의 지표 3개 값을 저장한다. 새 실적이 반영되면 "등록 때 87% → 지금 95%"처럼 나란히 보여준다.
- **데이터:** F-12 테이블에 메모 열과 등록 시점 값 열을 더한다. F-13 알림 본문에도 쓸 수 있다.
- **주의:** 주가 수익률은 넣지 않는다. 넣으면 매매 성과를 추적하는 기능이 되어 서비스 방향과 어긋난다.
- **붙는 곳:** F-12·F-13 · **난이도:** 중간
