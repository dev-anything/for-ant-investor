## 1. 제품 개요

### 1-1. 한 줄 정의

**재무 레이더** (가칭): 초보 개인투자자가 종목을 검색하면 그 회사의 최근 3개년 실적과 재무 변화를 쉽게 보여주고, 재무 조건으로 종목을 걸러볼 수 있는 웹앱.

### 1-2. 배경

- 한국폴리텍대학 2학년 2학기 「AI프로그래밍」 과제. 공공데이터를 활용한 **비영리** 서비스.
- 유료 기능·광고를 붙이지 않는다 (KRX 데이터 공공누리 제4유형 상업적 이용금지, Vercel Hobby 비상업 조건).

### 1-3. 대상 사용자

- 주식을 막 시작한 대학생·사회초년생 개인투자자.
- 유튜브·커뮤니티·지인 추천으로 종목을 고르고, 그 회사가 돈을 버는지·빚이 느는지는 확인하지 않는 사람.

### 1-4. 해결할 문제

| 문제 | 서비스의 답 |
| --- | --- |
| 재무 정보가 어렵다 (DART 원문은 길고, 증권 앱은 숫자 표만 보여줌) | 지표 3개를 눈금·화살표로, 변화를 한 줄 문장으로 보여준다 |
| 변화를 보기 힘들다 (연도별 숫자를 직접 모아 계산해야 함) | 3개년 그래프와 "눈여겨볼 변화" 문장 |
| 조건으로 찾기 어렵다 (HTS 조건검색은 어려움) | 쉬운 문구의 필터 20개 + 문장으로 찾는 챗봇 |
| 어디서부터 봐야 할지 모른다 | 업종으로 둘러보기, 처음 읽는 순서 안내 |

### 1-5. 서비스 원칙 (모든 기능에 적용, 어기면 안 됨)

1. **매수·매도를 추천하지 않는다.** 재무 사실과 그 변화만 보여주고 판단은 사용자에게 맡긴다.
2. **금지 표현:** "사라/팔라", "좋은 회사", "살 만한", 목표가, 전망, "위험", "양호", "싸다/비싸다", "높을수록/낮을수록 좋아", "조심해", "좋아졌어" 등 권유·평가 표현을 **화면·문구·코드(변수명·주석 포함) 어디에도** 쓰지 않는다.
3. **신호등(초록·노랑·빨강)을 쓰지 않는다.** "안정성·수익성·성장성" 같은 평가하는 이름도 쓰지 않는다. 지표는 눈금 위 위치 + 방향 화살표로만 보여준다.
4. **색으로 좋고 나쁨을 말하지 않는다.** 방향 화살표는 한 가지 색. 적자 막대의 색 구분은 "음수"라는 사실 표시일 뿐 경고색(빨강)으로 쓰지 않는다.
5. **순위처럼 보이게 하지 않는다.** 목록의 기본 정렬은 가나다순. 사용자가 직접 누른 정렬만 값 순서.
6. **회사가 발표한 숫자만 쓴다.** 서비스가 근사·추정 숫자를 만들지 않는다 (예: 12월 결산 기준 재계산 안 함, 공시 안 된 배당수익률을 직접 계산 안 함).
7. **AI는 숫자나 의견을 말하지 않는다.** 챗봇은 정해진 필터 ID·종류 코드만 고른다.

## 3. 공통 요구사항

### 3-1. 용어·어투

- **사용자에게 말하는 문구는 친구처럼 말하는 반말("~했어", "~야")** 로 쓴다. 범위: 리포트카드 문장, 안내 문구, 챗봇 답, 툴팁, 웹 알림 본문, 알림 메일 본문.
  - 친근해도 권유·평가 표현은 넣지 않는다 (1-5).
- **존댓말 예외:** ① 출처 표시 ② 로그인·계정 화면 (로그인 창, 로그인 메일, 발송 안내, 탈퇴 확인) ③ 알림 메일의 **제목**과 **수신 거부 안내**.
- 필터 버튼 문구는 "~한 회사" 형태라 어투와 상관없이 그대로 쓴다.
- **"당기순이익" 대신 "순이익"** 을 화면 전체에서 쓴다 (그래프·필터·문장·마이페이지·알림). 툴팁에 "정식 이름은 당기순이익"을 적는다. 코드·DB 이름은 `net_income`.
- 이 문서에 적힌 문구는 모두 **확정**이다. 단, "UI와 같이 보며 수정할 수 있음"이 기본이라 화면을 만든 뒤 사용자 확인으로 바뀔 수 있다. 개발 에이전트가 임의로 바꾸지 않는다.

### 3-2. 출처 표시 (모든 화면 하단, 존댓말)

```
데이터 출처: 금융위원회·공공데이터포털(data.go.kr), 금융감독원 전자공시시스템(DART), 국가데이터처 통계분류포털 한국표준산업분류(제11차, kssc.mods.go.kr), 네이버 검색 API(뉴스)
공시 내용의 정확성은 각 회사에 책임이 있으며, 이 서비스는 데이터를 가공해 보여줍니다.
```

- 모든 페이지 공통 푸터 컴포넌트로 만든다. 알림 메일 하단에도 넣는다.
- 투자 책임 고지 문구는 10장 "구현 때 결정할 항목" 1번.
- 첫 줄 끝 `, 네이버 검색 API(뉴스)`는 F-18 기사 표시에 맞춰 2026-11-22 사용자 확인으로 추가했다 (10장 25번). 웹 화면 푸터에만 넣고, 네이버 데이터가 없는 알림 메일 하단은 기존 첫 줄을 쓴다. 둘째 줄("공시 내용의 정확성은…")과 기사 영역 자체의 네이버 표시(F-18)는 별개다.

### 3-3. 라이선스에 따른 표시 규칙

- **KRX 값(종목명·종목코드·시장구분)은 DB에 원본 그대로** 있다. 표시할 때만 가공한다 (예: 종목코드 앞 `A` 제거 → `short_code` 열 사용).
- **한국표준산업분류 이름은 줄이거나 바꾸지 않는다.** 대분류 이름은 포털 표기(예: `제 조 업`)로 저장되어 있어 **화면에서만 공백을 정리**한다 (`제조업`). 쉬운 이름을 따로 짓지 않는다.

### 3-4. 화면 기준

- **PC 우선 반응형.** PC 화면을 기준으로 설계하고, 작은 화면(폭 360px 이상)에서도 깨지지 않게 한다.
- 설치 없는 웹. 로그인 없이 모든 조회 기능을 쓴다.

### 3-5. 정보 구조

**상단 메뉴 (모든 화면, 초기 개발 방식 — 화면 배치 확인 후 바뀔 수 있음)**

| 순서 | 메뉴 | 화면 | 단계 |
| --- | --- | --- | --- |
| 1 | 종목 검색 | 첫 화면 (검색창) | MVP |
| 2 | 조건으로 찾기 | 스크리너 (F-07, F-10) | MVP |
| 3 | 업종으로 둘러보기 | 업종 목록 (F-15) | 2차 |
| 오른쪽 | 로그인 / 마이페이지·로그아웃 | F-11, F-12 | 확장 |

- 기사 목록 화면 `/news`(F-18)는 **상단 메뉴에 넣지 않는다.** 첫 화면의 `기사 더 보기 →` 링크로만 들어간다.

**첫 화면 (위에서 아래):** 검색창 → 바로가기 줄 → 경제 기사 (2차).

- `어떤 회사를 찾을지 모르겠다면 → 조건으로 찾기` (MVP)
- `회사 이름을 모르겠다면? 업종으로 둘러보기 →` (2차)
- 바로가기 줄 아래: **일반 경제 기사 5개** + `기사 더 보기 →` (→ `/news`) (F-18, 2차)

**종목 화면 구성 (위에서 아래 순서, 금융회사도 같은 순서 — 없는 영역만 빠짐)**

1. **머리:** 회사 이름 + 그 아래 정보 줄 `005930 · KOSPI · {중분류 이름} · {M}월 결산`
   - 업종 이름은 누르면 F-15의 그 업종 목록으로 간다 (툴팁 "같은 업종 회사를 둘러볼 수 있어."). 2차 전에는 글자로만 둔다.
   - 결산월은 **12월 결산이 아닌 회사만** 표시한다.
   - 첫 방문 알림 띠와 "읽는 순서" 버튼 (F-16, 2차)
   - "추적하기" 버튼 (F-12, 확장)
2. **리포트카드** (F-05): 자본잠식 안내 → "눈여겨볼 변화" 문장 → 지표 3개 눈금
3. **실적 그래프** (F-02)
4. **주가 수준 PER·PBR** (F-09)
5. **배당 카드** (F-14)

- 순서 이유: 문장을 먼저 읽고 그래프로 숫자를 확인한다. 주가가 섞인 값(PER·PBR·배당수익률)은 재무를 본 뒤에 둔다 (먼저 두면 싸다·비싸다로 읽힘). 기사·공시는 재무 사실을 다 본 뒤 맨 아래에 둔다 (외부 글이 재무 읽기보다 앞서지 않게). 탭으로 나누지 않는다.

### 3-8. 숫자 표시 규칙

- **금액 단위:** 1조 원 이상이면 `조 원`(소수 1자리), 그 미만이면 `억 원`(정수). DB 금액은 원 단위 정수다.
- **음수(적자):** 숫자 앞에 `-`. 막대는 0 아래로.
- **반올림:** DB·뷰 값은 반올림하지 않은 값이다. **화면에서만** 반올림한다. 기본: 비율(%)·배수(배)는 소수 1자리 (예: `87.3%`, `12.3배`). 7번 문장의 부채비율 값은 배치가 소수 1자리로 저장한 값을 그대로 쓴다.
- **연도:** `2025년` 형식. 사업연도 기준이다.
- **날짜:** `YYYY-MM-DD`.

## 4. 기능 요구사항

> 표기: Y1·Y2·Y3 = 화면에 보여주는 3개 연도, 오래된 → 최근. `company_summary.years`의 **뒤 3개**다 (`years`는 최대 4개년, 맨 앞 연도는 매출 증가율 계산용).

### F-01 종목 검색 (MVP)

**목표:** 종목코드와 종목명 어느 쪽으로도 종목을 찾아 종목 화면으로 보낸다.

**데이터:** 뷰 `v_search_targets` (검색 대상 = 목록에 있음 + KOSPI·KOSDAQ + 스팩 아님. 2026-11-17 기준 2,593개). 검색할 때 외부 API를 부르지 않는다.

**검색 규칙**

- 검색어가 **숫자로만** 되어 있으면 종목코드(`short_code`) **앞부분 일치** (`0059` → `005930`).
- 그 밖에는 **종목명**으로 찾는다. 대소문자와 띄어쓰기를 무시한다: 검색어를 소문자로 바꾸고 공백을 뺀 뒤 `search_name`(같은 방식으로 정규화된 생성 열, `pg_trgm` GIN 인덱스 있음)과 비교한다. `naver`, `삼성 전자`도 찾아진다.
- 종목코드에 영문자가 섞인 회사가 있다 (`0220W0`). 종목코드를 숫자로 가정하지 않는다 (영문자가 섞인 검색어는 종목명 검색으로 가지만, 종목코드 완전 일치도 함께 확인한다).
- 정렬: ① 종목코드·종목명 완전 일치 → ② 앞부분 일치 → ③ 중간 포함. 같은 순위끼리는 종목명 가나다순.
- **최대 10개.**

**연관검색어 표시**

- 형식 `삼성전자 (005930)`. 검색어와 일치하는 부분은 **굵게**.
- 1글자 이상 입력하면 표시. 입력이 멈추고 **약 0.3초 뒤** 검색 (디바운스).
- ↑↓로 이동, Enter로 선택, Esc로 닫기. 마우스 클릭으로도 선택.
- 결과가 없으면 **"검색 결과가 없어"**.
- 외국회사는 줄 끝에 `지원하지 않음`. 선택해도 이동하지 않는다.

**수용 기준**

- [ ] `005930`, `0059`, `삼성전자`, `삼성 전자`, `naver`(→ NAVER) 검색이 동작한다.
- [ ] 정렬 순서와 최대 10개가 지켜진다.
- [ ] 우선주 이름(`삼성전자우`)·스팩·코넥스 종목은 나오지 않는다.
- [ ] 외국회사는 `지원하지 않음`으로 보이고 선택해도 이동하지 않는다.
- [ ] 키보드만으로 검색·선택할 수 있다.

### F-02 최근 3개년 실적 그래프 (MVP)

**목표:** 종목의 최근 3개 사업연도 **매출액·영업이익·순이익**을 그래프로 보여준다.

**데이터:** `v_company_years`에서 `corp_code` = 그 회사, `is_display_year = true`인 행 (최대 3개). `revenue`, `operating_income`, `net_income`, `fs_div`, `fiscal_year`. 결산월은 `v_search_targets.acc_mt`.

**그래프 구성**

- **항목별 막대그래프 3개를 나란히** (매출액 / 영업이익 / 순이익). 매출이 이익보다 수십 배 커서 한 그래프에 그리면 이익 막대가 안 보이기 때문.
- 각 그래프의 가로축은 연도 3개. 세로축은 0에서 시작.
- **적자(음수)는 0 아래로 내려가는 막대**, 다른 색으로 구분 (경고색 아님, 1-5).
- 단위는 3-8 규칙. 막대 위에 값 표시.
- 마우스를 올리면 정확한 금액과 **전년 대비 증감률** (전년 값이 없거나 0이면 증감률 생략).
- 순이익 그래프 제목 옆 툴팁: "정식 이름은 당기순이익".
- 그래프 위 기준 표시: `기준: 연결재무제표 · 2023~2025 사업연도` (`fs_div` CFS = 연결재무제표, OFS = 별도재무제표). 회사마다 최신 연도가 달라도 연도 표시만 하고 따로 안내하지 않는다.
- 12월 결산이 아닌 회사는 정보 줄의 `{M}월 결산` 표시로 알린다. 숫자는 회사 발표 그대로.
- 차트 라이브러리: **Recharts**.

**예외**

- 3개 연도가 다 없으면 있는 연도만 그린다.
- 일부 항목만 null인 연도는 그 막대 자리에 **"제공되지 않음"**.
- 재무 데이터 없음: **"이 회사의 재무정보가 없어"** (리포트카드도 숨김).
- 금융회사: 매출액 그래프 없이 영업이익·순이익 2개 + 안내 **"금융회사는 매출액 항목이 없어서 영업이익과 순이익만 보여줘"**.

**수용 기준**

- [ ] 삼성전자(005930)의 2023~2025 매출액·영업이익·순이익이 DART 원문과 같다 (단위 변환 포함).
- [ ] 적자 연도가 있는 회사에서 막대가 0 아래로 그려진다.
- [ ] 별도재무제표 회사는 기준 표시가 `별도재무제표`로 나온다.
- [ ] 금융회사(예: KB금융)는 막대 2종과 안내 문구가 나온다.

### F-05 재무 리포트카드 (MVP)

**목표:** 재무 상태를 지표 3개로 보여준다. 현재 값이 어디쯤인지와 3년 동안 어느 방향으로 움직였는지를 보여주고, 좋다·나쁘다는 판단하지 않는다.

**구성 (위에서 아래)**

1. 자본잠식 안내 (해당 회사만)
2. **"눈여겨볼 변화"** 문장 영역
3. 지표 3개 눈금 + 방향 화살표

#### 지표 3개

| 제목 (화면) | 지표 | 계산 (뷰가 계산함) | `v_company_years` 열 |
| --- | --- | --- | --- |
| 빚이 얼마나 있나 | 부채비율 | 부채총계 ÷ 자본총계 × 100 | `debt_ratio` |
| 팔아서 얼마나 남기나 | 영업이익률 | 영업이익 ÷ 매출액 × 100 | `operating_margin` |
| 매출이 얼마나 늘었나 | 매출 증가율 | (당해 − 전년) ÷ 전년 × 100 | `revenue_growth` |

- 각 지표는 Y1~Y3 값 3개를 쓴다. 매출 증가율은 4개년 매출로 증가율 3개를 만든다 (뷰가 전년 행과 조인해 계산, 4년 전 자료가 없으면 Y1 증가율은 null).
- 뷰의 null 규칙: 금융회사면 3개 모두 null, 자본 ≤ 0이면 부채비율 null, 매출 ≤ 0이면 영업이익률 null, 전년 매출 ≤ 0이면 매출 증가율 null.
- 지표를 더 늘리지 않는다.

#### 표현: 눈금 위 위치 + 3년 방향 화살표

```
빚이 얼마나 있나
부채비율 87.0% ↘ 3년째 감소
0% ────●──────|────── 300%
              100%
(112.0% → 95.0% → 87.0%)
```

- 가로 눈금 위에 **최근 연도(Y3) 값**을 점으로 찍고, 값 3개를 아래에 적는다. "낮음/높음" 같은 등급 말은 쓰지 않는다.
- **눈금 범위 (지표마다 고정, 모든 회사 공통):**

| 지표 | 범위 | 기준선 | 기준선 툴팁 |
| --- | --- | --- | --- |
| 부채비율 | 0 ~ 300% | 100% | 빚과 자기 돈(자본)이 같아지는 지점이야. 좋고 나쁨을 가르는 기준은 아니야. |
| 영업이익률 | −50 ~ +40% | 0% | 이 선보다 아래면 영업적자야. |
| 매출 증가율 | −40 ~ +70% | 0% | 이 선보다 아래면 매출이 전년보다 줄었어. |

- 범위를 벗어난 값은 **점을 끝에 붙이고** 실제 수치를 글자로 보여준다.

**방향 화살표 규칙 (값 3개 a, b, c / 오래된 → 최근)**

| 모양 | 화살표 | 옆에 붙는 말 |
| --- | --- | --- |
| 두 번의 변화가 둘 다 **눈금 폭의 3% 이내** | → | 비슷한 수준 |
| a < b < c | ↗ | 3년째 증가 |
| a > b > c | ↘ | 3년째 감소 |
| 올랐다 내림 / 내렸다 오름 | ↕ | 오르내림 |
| 값이 2개뿐 | ↗ / ↘ | 전년보다 증가 / 전년보다 감소 |

- "비슷한 수준"을 먼저 판정한다. 폭: 부채비율 ±9%p, 영업이익률 ±2.7%p, 매출 증가율 ±3.3%p (눈금 폭 × 3%). 둘 중 하나라도 넘으면 아래 규칙대로.
- 값이 2개일 때 차이가 3% 폭 이내면 "비슷한 수준"으로 본다 (기본안, 10장 8번).
- 값이 1개 이하면 화살표 없이 값만.
- "비슷한 수준" 툴팁: **"3년 동안 변화가 아주 작아서 거의 그대로야."**
- 화살표는 **한 가지 색**.

#### 눈금을 못 그리는 경우 (`company_summary.capital_impairment` 사용)

| 경우 | 판별 | 처리 · 문구 |
| --- | --- | --- |
| 완전 자본잠식 | `capital_impairment = 'full'` (자본총계 ≤ 0) | 부채비율 눈금 자리에 **눈에 띄는 안내 상자**: "자본총계가 0 이하야 (완전 자본잠식). 회사가 가진 자산보다 빚이 더 많은 상태야." 숨기지 않는다. 거래소 규정 문장은 넣지 않는다 |
| 부분 자본잠식 | `capital_impairment = 'partial'` | 부채비율 눈금은 정상으로 그리고, 눈금 아래 한 줄 (완전 잠식보다 작게): "자본총계가 자본금보다 적어 (부분 자본잠식)." |
| 자본금 0·없음 | `capital_impairment = 'unknown'` | 자본잠식 표시 없음 |
| 매출액 0 또는 없음 | Y3 `operating_margin` null, 금융회사 아님 | 영업이익률 눈금 자리에 "매출액이 없어서 영업이익률을 계산할 수 없어." |
| 전년 매출 0 | 그 연도 `revenue_growth` null | 그 연도 칸만 "계산할 수 없어" |
| 재무 데이터 없음 | — | 리포트카드 전체 숨김 (F-02 안내만) |
| 금융회사 | `is_financial` | 지표 3개 눈금 없음. 문장 영역과 자본잠식 안내는 표시 |

#### "눈여겨볼 변화" 문장 (`company_summary.insights`)

배치가 판정해 **우선순위 순으로 전부** 저장해 둔다. 웹앱은 **앞에서 3개**를 문장으로 바꿔 보여준다.

| id | 문장 템플릿 | 조건 (참고, 배치가 판정) | 우선순위 | insights 필드 |
| --- | --- | --- | --- | --- |
| 1 | 매출은 늘었는데 영업이익률은 줄었어 | 최근 매출 증가 + 영업이익률 하락 | 3 | — |
| 2 | 매출은 줄었는데 영업이익은 늘었어 | 최근 매출 감소 + 영업이익 증가 | 3 | — |
| 3 | 영업이익은 흑자인데 순이익은 적자야 | 영업이익 > 0, 순이익 < 0 | 2 | — |
| 4 | {year}년에 영업이익이 흑자로 돌아섰어 | 전년 적자 → 최근 흑자 | 3 | `year` |
| 5 | {year}년에 영업이익이 적자로 돌아섰어 | 전년 흑자 → 최근 적자 | 1 | `year` |
| 6 | 영업적자가 {n}년째 이어지고 있어 | 최근 2개년 이상 연속 영업적자 (n = 2~4) | 1 | `n` |
| 7 | 부채비율이 1년 사이 {prev}%에서 {curr}%로 올랐어 | 올해 ≥ 전년 × 1.25 AND 오른 폭 ≥ 10%p | 3 | `prev`, `curr` |
| 8 | 영업이익은 적자인데 순이익은 흑자야 | 영업이익 < 0, 순이익 > 0 | 2 | — |

- `insights` 예: `[{"id":5,"year":2025},{"id":6,"n":3},{"id":7,"prev":120.5,"curr":160.2}]`
- 걸린 문장이 하나도 없으면 **영역을 아예 숨긴다.** "눈에 띄는 변화가 없어" 같은 문구를 쓰지 않는다 ("문제없는 회사"로 읽힐 수 있음).
- 문장에 해석·평가를 덧붙이지 않는다.

**수용 기준**

- [ ] 지표 3개의 값이 `v_company_years`와 같고, 화면에서만 소수 1자리로 반올림된다.
- [ ] 범위 밖 값(예: 부채비율 450%)이 눈금 끝에 붙고 실제 수치가 보인다.
- [ ] 화살표 규칙 5가지가 모두 맞게 나온다 ("비슷한 수준" 우선).
- [ ] `capital_impairment`가 full·partial인 회사에서 안내가 맞게 나온다.
- [ ] 문장은 최대 3개, insights 순서 그대로 나오고, 없으면 영역이 숨는다.
- [ ] 금융회사는 눈금이 없고 문장만 나온다.

### F-07 필터 검색 실행 — 스크리너 화면 (MVP)

**목표:** 필터를 골라 조건에 모두 맞는(AND) 종목 목록을 근거 숫자와 함께 보여준다. 사용자가 기준을 배우면서 쓰게 한다.

**진입:** 상단 메뉴 "조건으로 찾기", 첫 화면 바로가기.

**대상:** 검색 대상 중 `company_summary`가 있는 회사 (금융회사 포함, 외국회사·재무 없음 제외).

**검색:** `matched_filters @> '{고른 ID}'` (GIN 인덱스). 필터를 하나도 고르지 않았으면 목록을 보여주지 않고 필터 고르기 안내만 둔다 (기본안, 10장 11번).

**필터 고르기**

- 묶음 6개로 나눠 버튼을 보여준다. 각 버튼에 툴팁 (F-03).
- **최대 3개.** 4번째를 누르면 **"필터는 3개까지 고를 수 있어"**.
- **부딪히는 필터:** 하나를 고르면 짝 버튼이 흐려진다. 흐려진 버튼에 올리거나 누르면 **"'{고른 필터 문구}'와 함께 고를 수 없어"** (예: "'영업적자가 2년 이상 이어진 회사'와 함께 고를 수 없어").
- **13·14 포함 관계:** 하나를 고르면 다른 하나의 선택이 풀린다.

**결과 목록**

- 목록 위: **"조건에 맞는 회사 {N}개"**.
- 한 줄: 종목명(12월 결산이 아니면 `{M}월 결산` 표시) · 종목코드 · 시장 · **시가총액** · 고른 필터의 **근거 값 열** (F-03 표).
- **정렬:** 기본 **종목명 가나다순.** 열 제목을 누르면 그 값으로 정렬 (시가총액 포함). 기본 정렬을 값 순으로 하지 않는다 (순위표처럼 읽힘).
- 시가총액이 없는 회사는 `-`, 시가총액 정렬에서 맨 뒤.
- 시가총액 열 근처에 `시가총액은 보통주 기준, 주가 {YYYY-MM-DD} 기준` (`v_valuation.bas_dt`).
- **한 번에 보여줄 개수 선택 상자:** 10 / 20 / 50 (기본 10) + 목록 아래 페이지 번호.
- 종목을 누르면 종목 화면. **뒤로 돌아오면 고른 필터·정렬·페이지·개수가 그대로** (URL 쿼리에 담는 것을 기본안으로, 10장 12번).
- **0건:** "조건에 모두 맞는 회사가 없어. 필터를 하나 빼 봐."
- PER·PBR은 필터에도 열에도 넣지 않는다.

**금융회사가 빠질 때 안내**

- 필터 1~3·10~16 중 **하나라도 골랐을 때만** 결과 개수 옆에 한 줄: **"금융회사는 이 조건을 계산할 수 없어서 빠졌어."**
- 그 줄의 툴팁: **"금융회사는 매출액 항목이 없고, 예금이 부채로 잡혀서 부채비율을 일반 회사와 견줄 수 없어."**

**F-10 챗봇 자리:** 스크리너 화면 맨 위, 필터 버튼 위쪽 (2차에 붙임).

**수용 기준**

- [ ] 필터 1·13을 고른 결과 수가 `select count(*) from company_summary where matched_filters @> '{1,13}'`(검색 대상 한정)과 같다.
- [ ] 4번째 필터, 부딪히는 필터, 13·14 포함 관계 동작이 맞다.
- [ ] 기본 정렬은 가나다순이고, 열 제목으로 정렬이 바뀐다.
- [ ] 금융회사 빠짐 안내가 해당 필터에서만 나온다.
- [ ] 종목 화면에 갔다 돌아와도 상태가 남아 있다.

### F-08 업종 비교 (2차)

**목표:** 지표 3개를 같은 업종 회사들의 **가운데 값(중앙값)** 과 나란히 보여주고, 같은 업종 회사 목록을 볼 수 있게 한다.

**업종 묶음:** DART 업종 코드 앞 두 자리 = 한국표준산업분류 제11차 **중분류** (`division_code`, 이름 `division_name`). 지주회사도 DART 코드 그대로 따른다 (`64992`는 64 금융업 묶음).

**데이터:** `v_industry_medians` (중분류별 `debt_ratio_median`·`_n`, `operating_margin_median`·`_n`, `revenue_growth_median`·`_n`, `per_median`·`_n`, `pbr_median`·`_n`). 평균이 아니라 중앙값 (극단값 때문). 결산월이 다른 회사도 그대로 넣는다.

**화면**

- 리포트카드 눈금 3개 위에 업종 가운데 값을 **표시 하나로 더** 찍는다. 라벨 **"같은 업종 가운데 값 {값}"**.
- 가운데 값 툴팁: **"같은 업종 회사들을 줄 세웠을 때 한가운데 값이야. 이 업종 회사 {N}개로 계산했어."**
- 이 회사와 비교 한 줄: **"같은 업종 가운데 값보다 높아 / 낮아 / 같아"** (비교는 화면 표시 값(소수 1자리) 기준, 기본안). 평가 표현 없음.
- **최소 회사 수 3개.** 그 지표 값이 있는 회사(`_n`)가 3개 미만이면 가운데 값을 표시하지 않고 **"같은 업종 회사가 적어서 비교 값을 표시하지 않아."** (기준 숫자는 상수로 둔다. 대체안 5개)
- 업종 코드가 없는 회사: **"업종 정보가 없어."** (비교 없음)
- 버튼 **"같은 업종 회사 보기"** → 같은 업종 회사 목록.

**같은 업종 회사 목록 (지표 비교 목록)**

- 제목: **"{중분류 이름} 회사 {N}개"**
- 스크리너 결과 화면 모양을 다시 쓴다. 열: 종목명 · 종목코드 · 시장 · 부채비율 · 영업이익률 · 매출 증가율 (최근 연도). 기본 가나다순, 열 제목 정렬, 개수 선택 10/20/50 + 페이지.
- 정렬·페이지·개수는 URL 쿼리(`?sort=&dir=&page=&size=`)에 담고 서버가 다시 그린다 (링크 방식, 2026-11-20). 값이 null인 회사는 오름·내림 모두 맨 뒤 (기본안).
- F-15 업종 목록에서 **"지표로 견줘 보기"** 링크로도 온다.

**수용 기준**

- [ ] 삼성전자의 업종(26)의 가운데 값이 `v_industry_medians`와 같다.
- [ ] `_n < 3`인 지표는 가운데 값 대신 안내가 나온다.
- [ ] 금융회사 화면에는 지표 눈금이 없으므로 가운데 값도 없다.

### F-09 주가 수준 — PER·PBR (2차)

**목표:** 회사가 버는 돈과 회사 몫 재산에 비해 주가가 어느 정도인지를 같은 업종과 나란히 보여준다. 싸다·비싸다는 판정하지 않는다.

**데이터:** `v_valuation` (`per` = 시가총액 ÷ 최신 연도 순이익, `pbr` = 시가총액 ÷ 최신 연도 자본총계, `bas_dt`, `latest_year`, `mrkt_tot_amt`). **보통주 시가총액**만 쓴다. 업종 가운데 값은 `v_industry_medians.per_median`·`pbr_median`.

**화면 (리포트카드와 분리된 별도 영역, 실적 그래프 아래)**

| 쓰이는 곳 | 문구 |
| --- | --- |
| 영역 제목 | 주가 수준 |
| PER 제목 | 주가가 버는 돈의 몇 배인가 (PER) |
| PBR 제목 | 주가가 회사 자기 돈(자본)의 몇 배인가 (PBR) |
| 값 | {값}배 (예: 12.3배) |
| PER 툴팁 | 시가총액을 1년 순이익으로 나눈 값이야. 10배면 지금 시가총액이 1년 순이익의 10배라는 뜻이야. 계산: 시가총액 ÷ 순이익 |
| PBR 툴팁 | 시가총액을 자본(자산에서 빚을 뺀 회사 몫)으로 나눈 값이야. 계산: 시가총액 ÷ 자본총계 |
| PBR 1배 선 툴팁 | 시가총액과 회사 자본이 같아지는 지점이야. 좋고 나쁨을 가르는 기준은 아니야. |
| 순이익 적자 (`per` null) | 순이익이 적자여서 PER을 계산하지 않아. |
| 자본총계 0 이하 (`pbr` null) | 자본총계가 0 이하라서 PBR을 계산하지 않아. |
| 기준일 | 주가 {bas_dt} 기준 · 순이익·자본 {latest_year}년 기준 |
| 보통주 표시 | 보통주 시가총액 기준 |

- 표시 방식: F-05와 같은 **눈금 + 업종 가운데 값 표시**. "업종 대비 낮음/비슷/높음" 글자 판정은 쓰지 않는다.
- **눈금 범위:** PER **0~50배** (기준선 없음), PBR **0~5배** (기준선 1배). 범위 밖은 끝에 붙이고 수치를 글자로.
- 업종 가운데 값·최소 회사 수·업종 없음은 F-08 규칙과 문구를 그대로 쓴다.
- 금융회사도 똑같이 표시한다.
- 시세가 없는 종목(`v_valuation` 행 없음): 영역에 "주가 정보가 없어." (기본안, 10장 13번)

**수용 기준**

- [ ] 삼성전자 PER·PBR이 `v_valuation`과 같다 (2026-11-16 기준 PER 25.5, PBR 2.64 → 화면 `25.5배`, `2.6배`).
- [ ] 적자 회사는 PER 자리에 안내 문구가 나온다.
- [ ] 기준일 두 개가 표시된다.

### F-14 배당 정보 (2차)

### F-17 최근 공시 (2차)

**목표:** 그 회사가 최근 DART에 낸 공시를 **제목만** 보여주고 DART 원문으로 보낸다. 공시 내용을 해석하거나 요약하지 않는다.

**데이터:** DART 공시검색 `list.json` (5-8). `corp_code`로 조회, `sort=date`, `sort_mth=desc`. **DB에 저장하지 않는다.** 화면을 열 때 서버에서 부르고 **1시간** 캐시한다. 키는 기존 `DART_OPENAPI_KEY` (서버에서만).

**위치:** 종목 화면 맨 아래 — 배당 카드 다음, 출처 푸터 바로 위. F-18 회사 기사 칸과 **두 칸 나란히** (PC: 왼쪽 기사·오른쪽 공시, 좁은 화면: 위아래). 탭으로 나누지 않는다 (3-5).

**표시**

- **지분공시를 뺀 최신순 5개.** (거르는 방법은 구현 전 확인, 11장 19번)
- 한 줄: `{공시 제목} · {제출인} · {YYYY-MM-DD}` (`report_nm` · `flr_nm` · `rcept_dt`). 공시 제목은 받은 그대로 쓴다.
- 줄을 누르면 **DART 원문 뷰어를 새 탭**으로 연다: `https://dart.fss.or.kr/dsaf001/main.do?rcpNo={rcept_no}`.
- 칸 아래 **"더 보기"** → DART의 그 회사 공시 목록 (정확한 링크 형식은 구현 때 확인, 11장 20번).
- 공시 제목은 회사가 낸 사실만 적혀 있어 **금지 표현 검사를 하지 않는다.**
- 금융회사도 똑같이 표시한다.

**예외**

| 경우 | 처리 |
| --- | --- |
| DART 호출 실패 (오류·시간 초과·한도 초과) | 공시 칸에만 **"지금은 공시를 불러올 수 없어."** 재무 영역과 기사 칸은 그대로 |
| 최근 공시 0건 (`013`) | 10장 27번 기본안 |

- 공시 칸은 따로 불러온다 (기다리는 동안 재무 영역이 먼저 뜬다). 실패해도 화면 전체가 오류가 되지 않는다.

**수용 기준**

- [ ] 삼성전자 화면에 지분공시를 뺀 최신 공시 5개가 최신순으로 나오고, 제목·제출인·날짜가 DART 공시검색 결과와 같다.
- [ ] 줄을 누르면 새 탭에서 그 공시의 DART 원문이 열린다.
- [ ] DART 호출이 실패해도 재무 영역과 기사 칸은 정상이고, 공시 칸에만 실패 문구가 나온다.
- [ ] 같은 회사 화면을 1시간 안에 다시 열면 DART를 다시 부르지 않는다.
- [ ] DART 키가 브라우저 번들·응답에 나오지 않는다.

### F-18 경제 기사 (2차)

**목표:** 언론사 기사 **제목을 네이버 검색 결과 그대로** 보여주고 원문으로 보낸다. 서비스가 기사를 고르거나 빼거나 해석하지 않는다.

**데이터:** 네이버 검색 API 뉴스 — **NAVER API HUB** (5-8). **DB에 저장하지 않는다** (네이버 약관: 저장 금지, 임시 캐싱만 허용). 서버에서만 부른다. 키 `NAVER_API_HUB_KEY_ID`, `NAVER_API_HUB_KEY` (7-3).

**보여주는 곳 3개**

| 곳 | 개수 | 검색어 | 캐시 |
| --- | --- | --- | --- |
| 첫 화면 (바로가기 줄 아래) | 5개 + `기사 더 보기 →` (→ `/news`) | 일반 경제 검색어 (아래) | 30분 |
| `/news` 기사 목록 | 페이지 넘김 (한 페이지 개수는 10장 29번) | 첫 화면과 같음 | 30분 |
| 종목 화면 (공시 왼쪽 칸) | 5개 | **정식 종목명** (`itms_nm`), `sort=date` | 1시간 |

- `/news`는 상단 메뉴에 넣지 않는다 (3-5).
- **일반 경제 검색어:** "증시"처럼 시세·매매 쪽으로 쏠리는 검색어 대신 비교적 중립적인 검색어를 쓴다. 초안 `경제 정책`, `기업 실적`. 구현 전 **표본 검색으로 검증·조정**한다 (A안: 초안 → 검증, 11장 17번). 검색어 여러 개의 결과를 합쳐 다시 정렬하지 않는다 (가공 금지 — 구체 방식은 10장 28번).

**한 줄 표시 (세 곳 공통)**

- `{제목} · {도메인} · {시각}`. 응답에 언론사명 필드가 없어서 **`originallink`의 도메인**을 출처로 보여준다 (형식은 10장 30번).
- 줄을 누르면 **원문을 새 탭**으로 연다 (`originallink`, 없으면 `link`).
- **썸네일·요약(`description`)은 보여주지 않는다.**
- 제목의 `<b>` 태그를 지우고 HTML 엔티티를 풀어 **텍스트로만** 보여준다. 글자 내용은 바꾸지 않는다. HTML로 넣지 않는다 (`dangerouslySetInnerHTML` 금지).

**네이버 약관에 따른 표시 (지킬 것)**

- 기사 영역(첫 화면·`/news`·종목 화면 기사 칸)마다 **네이버 검색결과임을 표시**한다: BI 가이드의 네이버 로고 + 네이버 링크.
- **결과를 가공하지 않는다:** 받은 결과에서 기사를 빼거나 순서를 바꾸지 않고, 결과 사이에 다른 내용을 넣지 않는다. 제목을 줄이거나 고치지 않는다.
- 원문 링크와 출처(도메인)를 항상 붙인다.
- 광고·수익화와 섞지 않는다.
- **기사 데이터를 어떤 AI에도 넣지 않는다** (입력·학습·활용 금지). F-10 챗봇에도 넣지 않는다.

**서비스 원칙과 부딪힐 때**

- 기사 제목에는 1-5 금지 표현("살 만한", 전망 등)이 들어 있을 수 있다. 그래도 **거르거나 순서를 바꾸지 않는다** (네이버 약관). 1-5는 서비스가 직접 쓰는 문구에 적용하고, 기사 제목은 외부 인용으로 둔다.
- 대신 ① **검색어로 노이즈를 줄이고** ② 기사 칸 위에 안내 문구를 둔다: **"언론사 기사를 네이버 검색으로 그대로 보여주는 거야. 이 서비스의 의견이 아니야."**

**짧은 종목명 (종목 화면만)**

- 종목명이 짧으면 다른 회사 기사가 섞인다. 초안 기준: **한글 2글자 이하, 또는 영문·숫자만 3글자 이하.**
- 해당 종목은 기사 칸 대신 안내 **"이름이 짧아서 다른 회사 기사가 섞여. 네이버에서 직접 찾아봐 →"** + 네이버 뉴스 검색 링크(그 종목명, 새 탭, 링크 형식은 구현 때 확인). 공시 칸은 그대로.
- 기준과 해당 종목 수는 구현 전 검증한다 (11장 18번).

**실패·부가 기능**

- 기사 기능은 **끊길 수 있는 부가 기능**이다 (HUB 요금이 "한시적 무료"라 유료로 바뀔 수 있음).
- 키가 없거나 호출이 실패하면 기사 칸에만 **"지금은 기사를 불러올 수 없어."** 공시 칸·재무 영역·검색은 그대로.
- 기사 칸은 따로 불러온다 (기다리는 동안 나머지가 먼저 뜬다).
- 결과 0건은 10장 31번 기본안.

**수용 기준**

- [ ] 첫 화면에 기사 5개와 `기사 더 보기 →`가 나오고, `/news`에서 페이지를 넘길 수 있다. `/news`는 상단 메뉴에 없다.
- [ ] 삼성전자 화면 기사 칸에 "삼성전자" 검색 결과 최신순 5개가 네이버 응답 순서 그대로 나온다.
- [ ] 제목에 `<b>`·`&quot;` 같은 태그·엔티티가 보이지 않는다.
- [ ] 각 줄에 도메인·시각이 있고, 누르면 원문이 새 탭으로 열린다. 썸네일·요약은 없다.
- [ ] 기사 영역마다 네이버 로고·링크와 안내 문구가 있다.
- [ ] 짧은 종목명 종목은 기사 칸 대신 안내 + 네이버 링크가 나오고 공시 칸은 그대로다.
- [ ] 네이버 키를 지우거나 호출이 실패해도 기사 칸에만 실패 문구가 나오고 나머지는 정상이다.
- [ ] 기사 데이터가 DB·로그 파일에 저장되지 않고, F-10 챗봇 요청에 들어가지 않는다.
- [ ] 네이버 키가 브라우저 번들·응답에 나오지 않는다.

### F-15 업종으로 둘러보기 (2차)

**목표:** 회사 이름을 몰라도 업종에서 출발해 회사를 찾게 한다. 어떤 회사도 먼저 내세우지 않는다.

**진입:** 상단 메뉴 세 번째 "업종으로 둘러보기", 첫 화면 바로가기 "회사 이름을 모르겠다면? 업종으로 둘러보기 →", 종목 화면 정보 줄의 업종 이름.

**데이터:** `v_search_targets` (`division_code`, `division_name`, `section_code`, `section_name`), `ksic_classes` (`sort_order`), `v_valuation.mrkt_tot_amt`. 추가 API 호출 없음.

**업종 목록 화면**

```
업종으로 둘러보기
업종을 누르면 그 업종에 속한 회사를 볼 수 있어. 업종은 한국표준산업분류(제11차) 기준이야.

제조업 (회사 N개) ▾
  식료품 제조업 (회사 N개)
  의약품 제조업 (회사 N개)
정보통신업 (회사 N개) ▸
금융 및 보험업 (회사 N개) ▸
```

- **대분류로 묶고, 누르면 중분류가 펼쳐진다.** 대분류·중분류 모두 회사 수 표시 `(회사 23개)`.
- 이름은 **분류표 정식 이름 + 회사 수만.** 대표 회사 예시를 붙이지 않는다.
- 순서: 대분류·중분류 모두 **분류 번호순** (`sort_order`). 회사 수 순으로 정렬하지 않는다.
- 회사가 0개인 업종은 보여주지 않는다. 1~2개 업종은 보여준다.
- 대상 회사: 검색 대상 중 **외국회사 제외**, 업종 코드가 있는 회사. 금융회사 포함.
- 분류표에 없는 중분류 번호(`division_name` null)인 회사는 업종 코드 없는 회사처럼 목록에서 뺀다 (검색으로는 찾을 수 있음).

**회사 목록 화면 (중분류를 누른 뒤)**

```
의약품 제조업 · 이 업종 회사 N개                 지표로 견줘 보기
시가총액은 보통주 기준, 주가 YYYY-MM-DD 기준
종목명 ▲        종목코드   시장     시가총액
(회사)          000000    KOSPI    0조 0,000억
(회사) 3월 결산  000000    KOSDAQ   -
```

- 열: 종목명 · 종목코드 · 시장 · 시가총액. 지표 열 없음.
- 정렬: **가나다순(기본) / 시가총액순** 두 가지. 시가총액 없는 회사는 `-`, 시가총액순에서 맨 뒤.
- 개수 선택 10/20/50 (기본 10) + 페이지 번호.
- 정렬·페이지·개수는 URL 쿼리에 담고 서버가 다시 그린다 (F-08과 같은 링크 방식, 2026-11-20).
- **"지표로 견줘 보기"** → F-08 같은 업종 회사 목록.
- 종목을 누르면 종목 화면.
- 넣지 않는 것: 인기 종목, 많이 본 종목, 업종별 등락률·평균 수익률, 업종 안에서 필터 걸기.

**수용 기준**

- [ ] 대분류·중분류가 번호순이고 회사 수가 맞다 (회사 0개 업종 없음).
- [ ] 대분류 이름이 화면에서 공백 정리돼 보인다 (`제 조 업` → `제조업`).
- [ ] 종목 화면 업종 이름 → 그 업종 목록, 업종 목록 → F-08 목록 링크가 동작한다.

### F-16 처음 읽는 순서 안내 (2차)

**목표:** 종목 화면에서 무엇부터 읽을지 모르는 초보자에게 읽는 순서를 짚어 준다. **읽는 법만 알려 주고 평가하지 않는다.**

**구현:** **driver.js**. 화면을 어둡게 하고 한 영역씩 밝혀 말풍선. "다음"을 누르면 그 영역으로 자동 스크롤. 추가 API·DB 없음.

**시작 방식**

- **첫 방문 알림 띠** (화면을 가리지 않음): "어디부터 읽을지 모르겠다면 순서대로 짚어 줄게." + [읽는 순서 보기] 버튼 + ✕
  - 종목 화면에 들어올 때마다 뜬다. ✕를 누르거나 투어를 시작하면 그 뒤로 안 뜬다 (중간에 건너뛰어도 본 것으로 침).
  - 브라우저(`localStorage`)에 값 하나만 저장. 로그인과 잇지 않는다. 저장이 실패해도 화면은 정상 동작해야 한다.
- **고정 버튼 "읽는 순서"**: 종목 화면에 항상. "다시 보기" 역할.
- 위치: 종목 화면 위쪽(종목명 근처). 자동 시작하지 않는다.

**단계 (일반 회사 5단계)**

| 단계 | 이름 | 짚는 영역 | 말풍선 문구 |
| --- | --- | --- | --- |
| 1 | 얼마나 파나 | F-02 매출 막대 | 막대가 매출이야. 회사가 한 해 동안 판 금액이고, 3년 동안 어떻게 바뀌었는지 볼 수 있어. |
| 2 | 얼마나 남기나 | F-02 영업이익·순이익 막대 | 영업이익은 본업으로 남긴 돈이고, 순이익은 세금 같은 걸 다 빼고 마지막에 남은 돈이야. 0 아래로 내려간 막대는 적자란 뜻이야. |
| 3 | 빚은 얼마나 | F-05 부채비율 눈금 (여기서 한 번 위로 올라감) | 부채비율은 빚을 자본으로 나눈 값이야. 점이 이 회사의 위치고, 화살표는 3년 동안 움직인 방향이야. |
| 4 | 주가는 몇 배인가 | F-09 "주가 수준" 영역 전체 | PER은 주가가 회사가 버는 돈의 몇 배인지, PBR은 회사 자기 돈(자본)의 몇 배인지 보여줘. 눈금 위 표시는 같은 업종 회사들의 가운데 값이야. |
| 5 | 배당은 주나 | F-14 배당 카드 | 최근 3년 동안 한 주에 현금배당을 얼마 줬는지 보여줘. 배당수익률은 그해 배당 기준일 무렵 주가로 계산한 값이야. |

- 영업이익률·매출 증가율 눈금과 "눈여겨볼 변화" 문장은 짚지 않는다.
- F-17·F-18 기사·공시 칸(배당 카드 아래)은 투어 단계에 **넣지 않는다** (2026-11-20 결정). 일반 5단계·금융회사 3단계 그대로.
- 말풍선은 **모든 회사에 같은 고정 문구**. 회사 숫자를 넣지 않는다.
- 조작: "2/5" 표시, "이전" / "다음" / "건너뛰기", 마지막 단계는 "끝".
- 작은 화면: 말풍선을 화면 아래쪽에 고정.

**예외**

- **공통 규칙: 화면에 없는 영역의 단계는 건너뛰고 번호를 다시 매긴다.** (판별 기준에 기대지 않고 DOM에 영역이 있는지로 판단)
- **금융회사 (3단계):** 1/3 얼마나 남기나 → 2/3 주가는 몇 배인가 → 3/3 배당은 주나. 1/3 문구만 다름: "금융회사는 매출액 항목이 없어서 영업이익·순이익만 보여줘. 영업이익은 본업으로 남긴 돈이고, 순이익은 세금 같은 걸 다 빼고 마지막에 남은 돈이야."
- 값을 계산하지 못한 영역(PER 적자 안내, 완전 자본잠식 상자, 무배당 카드)도 영역이 있으면 그대로 짚는다.
- 재무 데이터 없음·외국회사 화면: 알림 띠와 버튼을 두지 않는다. 이 화면은 첫 방문으로 치지 않는다.

**수용 기준**

- [ ] 첫 방문 때 알림 띠가 뜨고, ✕ 또는 투어 시작 뒤에는 안 뜬다.
- [ ] 일반 회사 5단계, 금융회사 3단계로 번호가 다시 매겨진다.
- [ ] 단계마다 해당 영역으로 스크롤된다.

### F-10 조건 찾기 챗봇 — 문장 → 필터 (2차)

**목표:** 스크리너에서 사용자가 문장으로 조건을 입력하면 AI가 F-03 필터 중 맞는 것을 골라 준다. 실제 검색과 결과 표시는 스크리너가 한다.

**위치:** 스크리너 화면 맨 위, 필터 버튼 위쪽.

**AI의 역할 (엄격)**

- 입력 문장을 **필터 ID 목록(1~20)** 과 **지원하지 않는 조건의 종류 코드**, **조건이 아닌 말 여부**로만 바꾼다. JSON으로만 받는다.
- 숫자·의견·문장을 생성하지 않는다. 화면 문구는 전부 아래 **고정 문구**다.
- AI 출력이 정해진 ID·코드 밖이거나 JSON이 아니면 **버린다** (규칙 6과 같게 처리하거나 해당 항목만 버림).
- 호출은 **서버(API Route)에서만**. 키 `OPENROUTER_API_KEY`(이름은 구현 때 확정)는 `.env`·Vercel 환경변수.
- 모델: **OpenRouter 무료 모델** (`:free`). 구체 모델은 구현 때 그 시점 무료 목록에서 고른다. 하루 50회 제한 (시연 전 재확인).
- **무료 한도 보호 (2026-11-20):** ① 입력 문장을 정규화(앞뒤 공백 제거·연속 공백 하나로·대소문자 정리)한 값을 키로 AI 결과를 **1일 캐시**하고, 같은 문장은 AI를 다시 부르지 않는다. ② 하루 AI 호출 수를 Supabase 작은 테이블(5-7)에 세고, **상한(기본안 40회, 10장 33번)** 을 넘으면 AI를 부르지 않고 규칙 6 문구를 보여준다.
- 사용자 입력 문장을 외부 AI로 보낸다는 안내를 입력창 근처에 둔다 (기본안, 10장 15번).
- **F-18 기사 데이터(제목·링크·검색 결과)를 AI 요청에 절대 넣지 않는다** (네이버 약관: 데이터를 AI에 입력·학습·활용 금지). AI에 보내는 것은 사용자 문장과 필터 목록뿐이다.

**동작 규칙**

1. **고른 필터를 숨기지 않는다.** 필터 버튼이 눌린 상태로 바뀌고 "이 조건으로 찾았어: {필터 문구}, {필터 문구}".
2. **스크리너 규칙을 따른다.**
   - 부딪히는 두 조건이 있으면 **필터를 아무것도 적용하지 않고** "'{A}'와 '{B}'를 함께 만족하는 회사는 없어. 하나를 빼고 다시 적어 줘."
   - 4개 이상이면 **문장에 나온 순서대로 앞의 3개만** 적용하고 "필터는 3개까지라 앞의 3개만 골랐어: {…}. 나머지는 버튼에서 바꿔 골라 줘."
   - 13·14가 같이 오면 14만 남긴다.
   - 금융회사가 빠지는 필터가 있으면 F-07과 같은 안내.
3. **지원하지 않는 조건**은 종류 코드별 고정 문구로 알리고 나머지 조건만 적용한다.

   | 종류 코드 | 고정 문구 |
   | --- | --- |
   | `industry` 업종 | 업종 조건은 지원하지 않아. 업종은 '업종으로 둘러보기'에서 볼 수 있어. |
   | `dividend_yield` 배당수익률 | 배당수익률 조건은 지원하지 않아. |
   | `price` 주가·PER·PBR | 주가 조건은 지원하지 않아. |
   | `other` 그 밖 | 문장 속 일부 조건은 지원하지 않아서 빼고 찾았어. |

   - 지원하지 않는 조건만 있고 고를 필터가 없으면 문구만 보여주고 필터는 적용하지 않는다.
4. **조건이 아닌 말**("삼성전자 살까?")에는 답하지 않고 "조건으로 바꿀 수 없는 질문이야. 예: 부채비율이 낮고 매출이 늘어난 회사".
5. **한 번에 한 문장.** 입력할 때마다 새로 찾는다. 앞 입력을 이어받지 않는다.
6. **AI 응답 없음**(한도 초과·오류·시간 초과): 입력창만 숨기고 "지금은 문장으로 찾기를 쓸 수 없어. 아래 버튼으로 골라 줘." 필터 버튼은 그대로.

**화면 문구**

| 쓰이는 곳 | 문구 |
| --- | --- |
| 입력창 안내 글 | 찾고 싶은 회사를 문장으로 적어 줘 |
| 예시 문장 위 | 이렇게 적어 봐 |

**예시 문장 3개 (눌러서 바로 실행)**

| 예시 문장 | 고르는 필터 |
| --- | --- |
| 빚이 적고 매출이 늘어나는 회사 | 13 + 1 |
| 적자에서 흑자로 돌아선 회사 | 8 |
| 꾸준히 배당하는 회사 | 20 |

- 예시 문장은 AI를 거치지 않고 정해진 필터를 바로 적용한다 (하루 한도 절약, 기본안, 10장 16번).

**수용 기준**

- [ ] 예시 3개가 위 필터로 바뀐다.

### F-12 추적 종목·마이페이지 (확장)

**목표:** 로그인한 사용자가 지켜보고 싶은 종목을 등록하고 마이페이지에서 한눈에 본다.

**추적 등록**

- 종목 화면의 버튼 **"추적하기" / "추적 중"** (누르면 해제).
- 로그인 안 한 상태에서 누르면 **"로그인하면 종목을 추적할 수 있어."** + 로그인으로 안내. 로그인 뒤 그 종목이 추적 목록에 들어간다.
  - 방식 (2026-11-20): 매직링크의 돌아갈 주소에 `?next=/stocks/{code}&watch={code}`를 싣는다. `/auth/callback`에서 세션을 만든 뒤 `watch`가 검색 대상 종목코드인지 검사해 추적 목록에 넣고 종목 화면으로 보낸다 (다른 기기에서 메일 링크를 열어도 동작).
  - 이미 20개면 넣지 않고 종목 화면에 아래 상한 문구를 보여준다.
- **1인 20개 상한.** 넘기면 **"추적 종목은 20개까지 등록할 수 있어."** (DB insert 트리거가 막음 → 오류를 이 문구로 바꿔 보여줌).
- 재무 데이터가 없는 종목도 등록되고 "재무 데이터 없음"으로 보인다.

**마이페이지 구성**

- **추적 종목 카드 목록** (정렬: 최근 등록순 `created_at desc`)
  - 종목명(종목코드), 시장
  - 최근 3개년 매출액·영업이익·순이익 **작은 막대** (F-02와 같은 기준·단위), 최신 연도 전년 대비 증감률. 금융회사는 영업이익·순이익만.
  - "눈여겨볼 변화" 문장 **1개** (`insights` 첫 번째) + 더 있으면 **"외 {N}건"**. 카드를 누르면 종목 화면.
  - 자본잠식 회사는 그 사실 표시.
  - KRX 목록에서 빠진 종목(`stocks.is_listed = false`)은 **"목록에서 빠짐"** 표시와 함께 남긴다.
- 추적 종목 없음: **"아직 추적하는 종목이 없어. 종목 화면에서 '추적하기'를 눌러 봐."**
- **웹 알림 목록**과 읽지 않은 개수 (F-13)
- **알림 설정:** 이메일 수신 켜기/끄기 (`user_settings.email_opt_in`, 기본 꺼짐)
- **계정:** 로그아웃, 탈퇴

**데이터·보안:** `watchlist`(`user_id`, `srtn_cd`, `crno`, `created_at`). RLS로 본인 행만 읽기·추가·삭제.

### F-13 추적 종목 알림 (확장)

**목표:** 추적 종목에 변화가 생기면 웹 화면과 이메일로 알린다.

**알림 생성은 배치(Python)가 한다** (확장 단계에서 배치에 추가 구현). 웹앱은 `notifications`를 읽고 `read_at`만 갱신한다.

**알림 종류 3개**

| 종류 (`kind`) | 언제 | 웹 알림 본문 (반말) |
| --- | --- | --- |
| `new_results` 새 실적 반영 | 매월 5일 배치에서 새 사업연도 재무가 들어왔을 때 (종목당 1년 1번) | "{종목}의 {연도}년 실적이 반영됐어." + 다음 줄 매출액·영업이익(전년 대비 증감률) + "눈여겨볼 변화: {문장 1개}". **금융회사는 영업이익·순이익** |
| `delisted` 목록에서 빠짐 | 매일 KRX 배치에서 빠진 것을 처음 확인했을 때 | "{종목}이 KRX 상장종목 목록에서 빠졌어." (이유는 말하지 않음) |
| `audit_change` 감사의견 변경 | 새 사업보고서의 당기 의견이 전기와 다를 때 | "{종목}의 {연도}년 감사의견이 '{전년 의견}'에서 '{올해 의견}'으로 바뀌었어." |

- 새 실적 예시 (숫자는 모양 예시):
  > 농심의 2026년 실적이 반영됐어.
  > 매출액 3.5조 원 (전년보다 4% 증가), 영업이익 1,800억 원 (전년보다 12% 감소)
  > 눈여겨볼 변화: 매출은 늘었는데 영업이익률은 줄었어
- 감사의견: 한 연도 2행 중 **하나라도** 전년과 다르면 알리고, 달라진 쪽 의견을 DART 표기 그대로 쓴다 ("연결/별도" 이름은 붙이지 않음). 감사인만 바뀐 것은 알리지 않는다. 의견이 빈 행은 비교에서 뺀다.
- **같은 변화로 두 번 알리지 않는다:** `dedupe_key` = `{kind}:{srtn_cd}:{연도 또는 delisted_bas_dt}`, (`user_id`, `dedupe_key`) unique.
- KRX 목록이 하루 5% 넘게 줄어 반영하지 않은 날은 `delisted` 알림도 없다.
- 주가 변동 알림은 만들지 않는다.

**웹 알림:** 종목마다 하나씩 쌓는다 (묶지 않음). 마이페이지 알림 목록, 읽음 표시(`read_at`), 읽지 않은 개수.

**이메일 (수신을 켠 사용자만, Python 배치에서 Gmail SMTP로 발송)**

- **하루치를 한 통으로 묶는다** (`emailed_at is null`인 알림을 모아 보내고 `emailed_at` 기록).
- **생성·발송 위치 (2026-11-20):** `new_results`·`audit_change`는 DART 월 배치(개인 서버)가 새 연도를 넣을 때, `delisted`는 KRX 일 배치(GitHub Actions)가 처음 확인할 때 만든다. 메일은 GitHub Actions 매일 워크플로 마지막 단계 `batch/notify_mail.py`가 사용자별 한 통으로 묶어 보낸다 → 월 배치 알림 메일은 다음 평일 오후에 나간다 (6장).
- 메일 제목 (존댓말):
  - 실적만: "추적 종목 {N}개의 실적이 반영됐습니다"
  - 목록 이탈만: "추적 종목 {N}개가 상장종목 목록에서 빠졌습니다"
  - 감사의견만: "추적 종목 {N}개의 감사의견이 바뀌었습니다"
  - 섞이면: "추적 종목 {N}개에 새 소식이 있습니다"
- 본문: 웹 알림 본문들 (반말).
- 맨 아래: 출처 문구 + 투자 책임 고지 + 수신 거부 안내 (존댓말) **"이 메일을 더 받지 않으려면 여기를 눌러 주세요."** → `/unsubscribe?token=` **확인 화면**에서 [수신 거부] 버튼을 눌러야 꺼진다 (로그인 없이, `unsubscribe_token`). 링크를 여는 것(GET)만으로는 끄지 않는다 (메일 검사기·미리보기의 자동 열기 방지, 2026-11-20). 화면 문구는 10장 34번. `List-Unsubscribe` 메일 헤더는 쓰지 않는다.

- 키는 프로젝트 루트 `.env`(로컬), **Vercel 환경변수**(웹앱), **GitHub Secrets**(배치)에 둔다.
- **`.env` 파일을 열거나 읽거나 출력하지 않는다.** 코드에서는 변수 이름으로만 불러온다. `.env.example`에는 이름만.
- 비밀 키에 **`NEXT_PUBLIC_` 접두어를 붙이지 않는다.** `NEXT_PUBLIC_`은 publishable 키와 공개 설정에만.
- 키를 터미널 출력·로그·오류 메시지·응답·커밋 어디에도 남기지 않는다.
- 저장소는 **공개**다. 커밋 전에 키가 섞이지 않았는지 확인한다. `.gitignore`: `.env`, `.env.*`, `api_check_results/`, `ref/`, `logs/` (+ 웹앱 `node_modules/`, `.next/`, `.vercel/`).
- DART 인증키는 본인 키 하나만 쓰고 공유하지 않는다 (약관).

### 7-4. 데이터 읽기 방식

- 화면 데이터는 **API Route(서버)에서 Supabase를 읽어** 내려준다 (기본안, 10장 3번). 서버 컴포넌트에서 직접 읽어도 된다. 브라우저에서 DB를 직접 읽지 않는다 (로그인 세션 처리 제외).
- F-17·F-18은 서버에서 외부 API를 부르고 캐시한다 (5-8). 브라우저에서 DART·네이버를 직접 부르지 않는다.

### 7-5. 운영 주의

- Supabase 무료 플랜은 **7일 요청이 없으면 일시정지**된다. 매일 배치가 막아 주지만 **시연 전에 상태를 확인**한다.
- OpenRouter 무료 모델은 **하루 50회**(분당 20회). 시연 전 재확인. 웹앱은 같은 문장 1일 캐시 + 하루 상한 40회로 막는다 (F-10, 10장 33번).
- NAVER API HUB는 "한시적 무료"다. 유료 전환 공지가 오면 F-18을 끌 수 있게 둔다 (키를 지우면 기사 칸만 실패 문구). 시연 전 상태 확인.
- DART 하루 20,000건은 배치와 F-17이 같이 쓴다. 매월 5일 배치 날에는 사용량을 확인한다.
