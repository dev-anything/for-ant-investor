## 공통 사항

### 용어·어투 (2026-11-12 확정, 사용자 확정)

- **"당기순이익"은 화면 전체에서 "순이익"으로 통일한다** (그래프 F-02, 필터 F-03, 리포트카드 문장 F-05, 마이페이지 F-12, 알림 F-13). 툴팁에 "정식 이름은 당기순이익"이라고 적는다. 이유: 같은 값을 화면마다 다르게 부르면 다른 값으로 오해한다. (데이터·계정 이름을 말하는 설계 문서 안의 "당기순이익"은 그대로 둔다.)
- **서비스가 사용자에게 말하는 문구는 친구처럼 말하는 반말("~했어", "~야")로 쓴다** (사용자 지시). 범위: 리포트카드 문장, 안내 문구, 챗봇 답, 툴팁, 알림 본문.
  - 친근한 말투여도 "조심해", "좋아졌어" 같은 권유·평가는 넣지 않는다 (서비스 원칙 그대로).
  - **예외 (존댓말 또는 정해진 표기 유지):** ① 출처 표시 ② 로그인·계정 화면 (로그인 메일, 메일 발송 안내, 탈퇴 확인 등) ③ 자본잠식 안내 상자의 거래소 규정 문장 (규정 원문 말투) — **2026-11-16부터 쓰는 곳 없음** (F-05에서 규정 문장을 넣지 않기로 함) ④ 알림 메일의 제목과 수신 거부 안내 (메일 본문은 반말)
  - 필터 버튼 문구는 "~한 회사" 형태라 어투와 상관없이 그대로다.
  - 챗봇 예시 문장(사용자가 입력하는 말)은 자유롭게 둔다.
- 각 기능의 안내 문구는 이 어투로 바꿔 적었다 (2026-11-12). 사용자가 낱낱이 확인한 것은 5개 (스크리너 0건, 필터 개수 초과, 챗봇 "조건으로 바꿀 수 없는 질문", 금융회사 안내, "업종 정보가 없어")이고, 나머지는 2026-11-16 기능별 문구 확정 때 확정했다 (각 섹션 상태 줄). 실제 화면에서 수정할 수 있다.

### 개발 스택 (2026-11-15 확정, 사용자 확정)

기능 설계 세션이 사용자와 질문-답변으로 정했다. 웹앱 언어는 **TypeScript**, 수집 배치 언어는 **Python** (언어 두 개).

- **git + GitHub 저장소를 쓴다** (매일 시세 배치를 GitHub Actions로 돌리기 때문). 이때부터 CLAUDE.md 보안 규칙의 `.gitignore`(최소 `.env`, `api_check_results/`, `ref/`)와 값을 비운 `.env.example` 규칙이 적용된다.
- **키 위치:** 로컬은 `.env`, 매일 시세 배치(GitHub Actions)는 **GitHub Secrets**, 웹앱(Vercel)은 **Vercel 환경변수**에 `NEXT_PUBLIC_` 없이 넣는다. `.env`는 저장소에 올리지 않는다.

**구현 때 정할 것**

- F-05·F-09 눈금을 차트 라이브러리 없이 Tailwind로 직접 그릴지 (구현 때 정함).
- OpenRouter 구체 모델과 하루 50회 제한 (구현 때 모델 선택, 시연 전 한도 재확인).

### 종목 화면 구성

위에서 아래 순서. 금융회사도 같은 순서다 (지표가 없는 영역만 빠진다).

1. 회사 이름·종목코드 줄, 그 아래 정보 줄 (시장·업종 이름, F-15 둘러보기 링크), 첫 방문 알림 띠와 "읽는 순서" 버튼 (F-16)
2. **리포트카드** (F-05): "눈여겨볼 변화" 문장 + 지표 눈금과 방향 화살표. 그래프보다 위다 (질문 문장을 먼저 읽고 그래프로 확인)
3. **실적 그래프** (F-02): 3개년 매출·영업이익·순이익
4. **PER·PBR** (F-09): 주가가 섞인 값이라 재무 뒤에 둔다
5. **배당 카드** (F-14): 맨 끝 (F-16 투어 5단계 순서와 맞춘다)
6. 화면 하단 출처 문구 ([API조사.md 라이선스](./API조사.md#라이선스))

- 이유: 문장을 읽고 그래프로 확인하는 흐름, 주가와 견주는 값은 재무를 본 뒤에 둔다.
- 채택하지 않은 안: 리포트카드 → PER·PBR → 그래프 (PER·PBR이 먼저면 싸다·비싸다로 읽힘), 그래프 위·리포트카드 아래, 탭으로 나눔.
- 결정: 2026-11-14 순서 확정 (리포트카드 → 그래프 → PER·PBR), 2026-11-16 배당 카드를 맨 끝으로 확정. 화면 배치 확인 때 다시 볼 수 있다.

### 금융회사 처리 한눈에

> 금융회사는 매출액 계정이 없고 예금이 부채로 잡혀, 일반 회사와 같은 지표로 보여줄 수 없는 부분이 있다. 아래는 기능별 처리를 한곳에 모은 표다 (2026-11-17 통합, 규칙 내용은 그대로). 기능 섹션에는 요약과 이 절 링크만 둔다.

**판별 기준 (수집 뒤 검증)**

둘 중 하나라도 맞으면 금융회사로 본다.

- ① 주요계정에 "매출액" 계정이 없다 **OR**
- ② DART 업종 코드 앞 두 자리가 64~66 **AND** 업종 코드가 64992(지주회사)가 아니다

- 2026-11-15 초안 → **2026-11-16 A안 수정:** 64992는 업종 기준에서 빼고 매출액 계정 유무로만 판단한다. 한국표준산업분류 11차에서 `64992 지주회사`는 64 금융업 아래다 (KB금융이 이 코드). 일반 지주회사가 이 코드로 와도 지표가 숨겨지지 않게 하려는 것. 금융지주(매출액 없음)는 금융회사, 매출액이 있는 지주회사는 일반 회사다.
- 이유: 매출액이 없으면 매출 그래프·지표를 못 그린다. 금융업인데 매출액이 있는 회사는 부채비율 문제(예금이 부채로 잡힘)를 막는다. 단점: 64~66인데 매출액이 있는 회사는 매출 그래프가 숨는다.
- 채택하지 않은 안: 매출액 계정 없음만 / 업종 코드 64~66만 / 64992 전부 금융회사(B) / 수집 뒤 정함(C).
- **검증 (수집 뒤):** 64992 회사 목록과 매출액 계정 유무, 두 기준이 어긋나는 회사 수와 목록.

## 기능 설계

### F-01 종목 검색

- **목표:** 종목코드와 종목명 어느 쪽으로도 종목을 찾고, 고른 종목의 법인등록번호(`crno`)를 다음 기능에 넘긴다.
- **입력 / 출력:** 검색어 → 연관검색어 목록 `종목명 (종목코드)` → 선택한 종목의 종목명, 종목코드, 시장구분, `crno`
- **사용 데이터:** 금융위원회_KRX상장종목정보 (단축코드, 종목명, 시장구분, 법인등록번호)

**데이터 준비**

- 검색할 때마다 API를 부르지 않는다. 상장종목 목록을 하루 1회 받아 서버(DB 또는 JSON 파일)에 저장하고, 검색은 저장된 목록에서 한다.
- 최신 기준일자를 먼저 알아낸 뒤(`numOfRows=1`) 그 `basDt`로 전체 목록을 받는다. 같은 종목이 날짜별로 중복 저장되지 않게 한다.
- 종목코드는 원본(`A005930`)으로 저장하고, 검색·표시용으로 `A`를 뗀 6자리를 함께 둔다.
- 대상: 코스피·코스닥 상장 주식. 코넥스(107건)는 MVP에서 제외한다.
- **스팩은 제외한다.** 종목명(`itmsNm`)에 "스팩"이 들어간 종목(67건, 모두 코스닥)을 검색 목록에서 뺀다. 원본 값은 바꾸지 않고, 목록을 만들 때 걸러내기만 한다.

**검색 규칙**

- 검색어가 **숫자로만 되어 있으면** 종목코드로 찾는다. 앞부분 일치 (`0059` → `005930`).
- 그 밖에는 **종목명**으로 찾는다. 대소문자와 띄어쓰기를 무시한다 (`naver`, `삼성 전자`도 검색됨).
- 정렬 순서: ① 종목코드·종목명 완전 일치 → ② 앞부분 일치 → ③ 중간 포함. 같은 순위끼리는 종목명 가나다순.
- 최대 10개까지 보여준다.

**연관검색어 표시**

- 형식: `삼성전자 (005930)`. 검색어와 일치하는 부분은 굵게 표시한다.
- 1글자 이상 입력하면 표시한다. 입력이 멈추고 약 0.3초 뒤에 검색한다 (디바운스).
- 방향키 ↑↓로 이동하고 Enter로 선택, Esc로 목록을 닫는다. 마우스 클릭으로도 선택한다.
- 결과가 없으면 "검색 결과가 없어"를 보여준다 (2026-11-12 반말 어투로 바꿈, 초안).

**예외 처리**

- 우선주(예: `삼성전자우`)는 KRX상장종목정보에 오지 않는다 (2026-11-09 확인). 따로 처리할 필요는 없고, 우선주 이름이나 코드로 검색하면 "검색 결과가 없어"가 나온다.
- 외국회사는 `crno`가 `0000000000000`으로 온다. 목록에 `지원하지 않음`으로 표시하고 선택해도 그래프로 넘어가지 않는다.

### F-02 최근 3개년 실적 그래프

- **목표:** F-01에서 고른 종목의 최근 3개 사업연도 **매출액·영업이익·당기순이익**을 그래프로 보여준다.
- **입력 / 출력:** 종목 → 연도별 세 항목 값 → 그래프
- **사용 데이터:** **DART 단일회사 주요계정** (2026-11-12 변경) — 계정 "매출액", "영업이익", "당기순이익(손실)". F-04가 저장한 값을 읽는다.
  - 2026-11-12부터 안 씀

**데이터 조회**

- "최근 3개년" = 데이터가 있는 가장 최근 사업연도부터 거꾸로 3개. DART 최신 사업보고서(`reprt_code=11011`) 1회 호출로 당기·전기·전전기 3개년을 받는다 (2026-11 현재 2023~2025).
- 연결 기준(`fs_div=CFS`)을 우선 사용하고, 없으면 별도(`OFS`)를 쓴다. 세 연도는 같은 기준으로 맞춘다. 기준이 섞이면 그래프 아래에 표시한다. (표본 51개 중 11개는 별도만 있었다.)
- 금액은 **쉼표가 들어간 문자열**이므로 쉼표를 빼고 숫자로 바꾼다. 같은 계정이 두 번 오는 경우의 처리 규칙은 F-04 할 일.
- **회사마다 최신 연도가 달라도 연도 표시만 한다** (2026-11-11 결정). 회사별로 데이터가 있는 최신 3개년을 보여주고, 그래프 위의 "기준: 연결재무제표 · 2023~2025 사업연도" 표시로 연도를 알린다. "2025 사업연도 자료는 아직 없습니다" 같은 추가 안내는 넣지 않는다.
- **결산월: 12월 결산이 아닌 회사에만 "3월 결산"처럼 표시한다** (2026-11-12 F-08 토론에서 변경). 12월 결산 회사에는 아무것도 붙이지 않는다. 숫자는 회사가 발표한 그대로 두고 12월 기준으로 다시 계산하지 않는다. 자세한 내용은 F-08 "결산월 표시".
  - 업종 때문에 기업기본정보를 어차피 부르게 돼 결산월(`enpStacMm`, 최신 이력)을 추가 비용 없이 얻을 수 있어 바뀜.
  - 결산월은 **DART 기업개황 `acc_mt`**에서 가져온다 (2026-11-12 변경. 기존: 기업기본정보 `enpStacMm`). 업종과 같은 호출로 얻는다.

**그래프 구성**

- **항목별 막대그래프 3개를 나란히** 놓는다 (매출액 / 영업이익 / 순이익). 화면에서는 "당기순이익" 대신 **"순이익"**이라고 쓰고, 툴팁에 "정식 이름은 당기순이익"을 적는다 (2026-11-12, 공통 사항 "용어·어투"). 각 그래프의 가로축은 연도 3개다.
  - 이유: 매출액이 이익보다 수십 배 커서, 한 그래프에 같이 그리면 이익 막대가 거의 보이지 않는다.
- 세로축은 0에서 시작한다. **적자(음수)는 0 아래로 내려가는 막대**로 그리고 다른 색으로 구분한다.
- 단위는 금액 크기에 맞춰 자동으로 고른다: 1조 원 이상이면 `조 원`(소수 1자리), 그 미만이면 `억 원`(정수).
- 막대 위에 값을 표시하고, 마우스를 올리면 정확한 금액과 전년 대비 증감률을 보여준다.
- 그래프 위에 `기준: 연결재무제표 · 2023~2025 사업연도`처럼 기준과 연도를 표시한다.
- **화면 위치 (2026-11-14 확정):** 리포트카드(F-05)와 같은 종목 화면에 두고, **리포트카드 아래**에 놓는다. 그래프는 리포트카드의 "눈여겨볼 변화"를 숫자로 확인하는 역할이다 (F-05 "화면 위치").
  - 종목 화면 순서는 [종목 화면 구성](#종목-화면-구성)을 따른다.
  - F-16 처음 읽는 순서 안내가 1단계에서 이 그래프의 매출 막대, 2단계에서 영업이익·순이익 막대를 짚는다 (2026-11-14).

**예외 처리**

- 3개 연도가 다 없으면 있는 연도만 그린다. 하나도 없으면 "공개된 재무정보가 없어"를 보여준다 (초안).
- **DART에서도 데이터가 없는 회사** (주요계정 `status` `013` "조회된 데이타가 없습니다", 예: 한화머시너리앤서비스홀딩스): 안내 문구 초안 **"이 회사의 재무정보가 없어"** (2026-11-12, 반말 어투 초안). 리포트카드도 숨긴다 (F-05).
- **금융회사 (확정 A "있는 것만 보여준다", 2026-11-12):** 영업이익·순이익 막대만 그린다. 매출액 막대, 리포트카드 지표 3개, 매출 관련 문장은 쓰지 않는다. 안내 문구 "금융회사는 매출액 항목이 없어서 영업이익과 순이익만 보여줘" (사용자 확인, 2026-11-12). 판별 기준과 나머지 처리는 [금융회사 처리 한눈에](#금융회사-처리-한눈에).
- 일부 항목만 빈 값으로 오는 경우는 그래프 대신 "제공되지 않음"으로 표시한다.

**부딪히는 필터 (2026-11-12 확정)** — F-07·F-10이 사용

같이 고르면 반드시 0건인 짝 10쌍. 조건을 논리로 따져 만든 것이라 숫자 기준이 바뀌어도 그대로다.

| --- | --- |

| 3 ↔ 2 | 최근 매출이 줄었는데 1년 사이 늘 수 없음 |
| 3 ↔ 12 | 같은 이유 (12번은 최근 매출 증가) |

| 11 ↔ 12 | 방향 반대 |

- 20번과 부딪히는 짝은 없다 (2026-11-13).
- 부딪히지 않는 짝 (참고): 4와 8 (적자가 줄다가 흑자가 된 회사), 19와 18 (자본이 늘고 있지만 아직 자본금에 못 미치는 회사).
- 화면 동작: 필터를 고르면 부딪히는 필터 버튼이 흐려지고, 그 버튼에 올리거나 누르면 "'영업적자가 2년 이상 이어진 회사'와 함께 고를 수 없어"처럼 이유를 보여준다 (F-07). 챗봇(F-10)도 이 목록을 써서, 문장이 부딪히는 두 조건을 담으면 필터를 적용하지 않고 "'{A}'와 '{B}'를 함께 만족하는 회사는 없어. 하나를 빼고 다시 적어 줘."라고 알린다 (2026-11-16 확정, ). 13·14를 같이 고르면 더 좁은 14번만 남긴다.

**설계 원칙**

- 문구는 결과가 좋다·나쁘다를 단정하지 않고 사실만 말한다. "좋은 회사", "살 만한 회사" 같은 문구는 쓰지 않는다.
- 각 필터 옆에 계산식을 툴팁으로 보여줘, 사용자가 기준을 배우면서 쓰게 한다.
- 여러 필터를 고르면 모두 만족하는 종목만 보여준다 (AND).
- 숫자 기준(10%, 20%, 100%, 50%)은 초안이다. 수집한 전체 종목(약 2,570개)에 적용해 결과 수를 보고 조정한다.

### F-05 재무 리포트카드

- **목표:** 종목의 재무 상태를 지표 3개로 보여준다. 각 지표의 현재 값이 어디쯤인지와 3년 동안 어느 방향으로 움직였는지를 보여주고, 좋다·나쁘다는 판단하지 않는다.
- **입력 / 출력:** 종목 → 지표 3개 각각의 값 3개, 방향 화살표, 눈금 위 현재 위치
- **사용 데이터:** **DART 주요계정** (부채총계, 자본총계, 자본금, 영업이익, 매출액. 2026-11-12 요약재무제표에서 변경). F-02와 같은 기준(연결 우선)·같은 연도를 쓴다.
- **부채비율은 부채총계 ÷ 자본총계로 직접 계산한다** (2026-11-12). 금융위 API가 주던 `fnclDebtRto`는 더 이상 없다.

**신호등을 쓰지 않는다** (2026-11-12 결정)

- 초록·노랑·빨강 신호등과 등급 기준표는 쓰지 않는다. 색이 "좋다/나쁘다"를 대신 말해 서비스 원칙(판단하지 않고 사실만 보여줌)과 부딪히고, 초록 세 개가 "사도 되는 회사"로 읽힐 수 있다.
- 신호등 규칙 표는 2026-11-12에 폐기해 문서에서 지웠다 (`docs/결정기록.md` 참고).

**지표 3개와 제목**

- "안정성·수익성·성장성" 같은 영역 이름은 화면에 쓰지 않는다. 이름 자체가 평가하는 말이고, 지표 하나가 그 영역 전체를 말해주지 못한다 (부채비율은 빚의 크기만, 매출 증가율은 매출만 보여줌).
- 질문형 제목을 쓴다.

| 제목 | 지표 | 계산 |
| --- | --- | --- |
| 빚이 얼마나 있나 | 부채비율 | 부채총계 ÷ 자본총계 |
| 팔아서 얼마나 남기나 | 영업이익률 | 영업이익 ÷ 매출액 |
| 매출이 얼마나 늘었나 | 매출 증가율 | (당해 − 전년) ÷ 전년 |

- 지표는 더 늘리지 않는다 (초보자에게 어려워짐).
- **매출 증가율은 4개년 매출로 증가율 3개를 만든다.** 다른 두 지표와 같은 모양(값 3개 + 화살표)으로 보여주기 위해서다. 4년 전 자료가 없으면 있는 값만 보여준다.
  - 금융위 API 기준. **DART 사업보고서는 1회에 3개년만 온다.** 4년 전 매출은 전년도 사업보고서(전전기)를 한 번 더 불러야 한다 (2026-11-12, 문서 반영 세션이 발견한 영향).
  - **→ 4개년 유지로 확정 (2026-11-12, 사용자 확정).** 한 해 전 사업보고서를 한 번 더 불러 4개년을 맞춘다 (F-04). 이유: 부채비율·영업이익률은 3년 방향을 보여주는데 매출 증가율만 값 2개면 지표끼리 기준이 달라진다. 채택하지 않은 안: 3개년으로 줄여 증가율 2개만 표시.

**표현 방식: 눈금 위 위치 + 3년 방향 화살표**

```
부채비율 87% ↘ 3년째 감소
0% ────●──────────── 300%
        (112% → 95% → 87%)
```

- 지표마다 가로 눈금 위에 현재 값을 점으로 찍고, 값 3개의 방향을 화살표로 보여준다. "낮음/높음" 같은 등급 말은 쓰지 않는다.
- **방향 화살표 규칙:**

| 값 3개의 모양 | 화살표 | 옆에 붙는 말 |
| --- | --- | --- |
| 계속 오름 | ↗ | 3년째 증가 |
| 계속 내림 | ↘ | 3년째 감소 |
| 올랐다 내림 / 내렸다 오름 | ↕ | 오르내림 |
| 거의 그대로 | → | 비슷한 수준 |
| 값이 2개뿐 | ↗ 또는 ↘ | 전년보다 증가 / 감소 |

- 화살표는 **한 가지 색**으로 통일한다. 지표마다 "좋은 방향"을 정하지 않기 위해서다.
- 변화 폭이 작으면 "비슷한 수준"으로 보여주는 기준을 둔다.
  - **기준 (2026-11-15 초안, 사용자 확정): 두 번의 변화(Y1→Y2, Y2→Y3)가 둘 다 눈금 폭의 3% 이내면 "비슷한 수준(→)".** 지금 범위로는 부채비율 ±9%p, 영업이익률 ±2.7%p, 매출 증가율 ±3.3%p (2026-11-17 범위 조정 뒤). 눈금 범위가 바뀌면 같이 따라간다. 둘 중 하나라도 기준을 넘으면 기존 규칙(오름·내림·오르내림)대로.
  - 채택하지 않은 안: 지표마다 고정 숫자(예: ±5%p/±1%p/±2%p).
  - 검증 (수집 뒤): 지표마다 "비슷한 수준" 회사 비율을 세어, 너무 많거나(예: 절반 이상) 거의 없으면 조정.
- **눈금 범위는 지표마다 고정**한다. 모든 회사가 같은 눈금을 쓴다. 범위를 벗어난 값은 점을 끝에 붙이고 실제 수치를 글자로 보여준다. 상장사 분포 기준 눈금은 쓰지 않는다.
  - **범위 (2026-11-17 수집 뒤 조정, 사용자 확정):** 부채비율 **0~300%** (기준선 100%, 2026-11-15 그대로), 영업이익률 **−50~+40%** (기준선 0%), 매출 증가율 **−40~+70%** (기준선 0%). 처음 초안은 영업이익률 −20~+30%, 매출 증가율 −30~+50%였다.
  - 검증 (수집 뒤): 범위 밖 회사가 **양쪽 끝 합쳐 10%를 넘으면** 범위를 넓힌다. 2026-11-17 1차 결과: 범위 밖 부채비율 5.2%, 영업이익률 15.9%→9.1%, 매출 증가율 12.1%→7.7% (넓힌 뒤).
    - 범위 밖 영업이익률은 아래쪽에 몰려 있었다 (아래 13.5%, 위 2.5%, 하위 5% −83.8%). 그래서 아래쪽을 더 넓혔다.
- **기준선:**
  - 영업이익률·매출 증가율: 0% 위치에 선 (흑자/적자, 증가/감소가 갈리는 지점)
  - 부채비율: 100% 위치에 선 (부채와 자본이 같아지는 지점). 좋고 나쁨의 기준이 아니라 계산상의 의미라는 점을 툴팁에 적는다.

**표시 방식**

- 리포트카드(F-05·F-08)와 같은 **눈금 + 같은 업종 가운데 값**. 눈금 위에 이 회사 위치를 찍고 업종 가운데 값을 표시 하나로 더 찍는다.
- 계획서의 "업종 대비 낮음 / 비슷 / 높음" 글자 표시는 쓰지 않는다. "낮음"은 서비스가 내리는 판정이고 초보자에게 "싸다"로 읽힌다 (신호등 폐기와 같은 이유).
- **리포트카드와 영역을 분리**한다. 리포트카드는 회사가 발표한 재무 사실이고, 이건 주가가 섞인 값이다. **실적 그래프(F-02) 아래 별도 영역**에 둔다 ([종목 화면 구성](#종목-화면-구성)).
  - 이유: 재무 사실인 리포트카드와 그래프가 붙어 있어 문장을 읽고 바로 그래프로 확인한다. 주가와 견주는 PER·PBR은 재무를 본 뒤에 본다. 서비스 목적(재무 변화)이 먼저 보인다.
  - 종목 화면에서의 순서는 [종목 화면 구성](#종목-화면-구성)을 따른다.
  - 채택하지 않은 안: B "리포트카드 → PER·PBR → 그래프" (문장과 그래프 사이가 벌어짐), C "PER·PBR → 리포트카드 → 그래프" (주가 수준부터 보여 '싸다·비싸다'처럼 읽히고 서비스 방향과 어긋남).
  - 범위: 이 세 영역의 순서만. F-14 배당 카드 등 나머지 카드 순서는 화면 배치 때. → **2026-11-16: 배당 카드는 PER·PBR 바로 뒤, 맨 끝** (F-14).

  - PBR 1배는 시가총액이 장부상 자본과 같아지는 지점이다. F-05 부채비율 100%선처럼 툴팁에 "계산상 의미, 좋고 나쁨의 기준 아님"이라고 적는다. PER에는 계산상 기준점이 없어서 선을 두지 않는다.

### F-10 조건 찾기 챗봇 (문장 → 필터)

- **목표:** 스크리너(F-07)에서 사용자가 문장으로 조건을 입력하면, AI가 F-03 필터 중 맞는 것을 골라 준다. 예: "빚 적고 매출 느는 회사" → "부채비율이 100% 이하인 회사" + "매출이 2년 연속 늘어난 회사" (2026-11-12 확정 문구 기준).
- **방향 변경 (2026-11-12):** 계획서의 "리포트 2~3문장 AI 요약"은 **하지 않는다.** 리포트카드에 규칙 기반 "눈여겨볼 변화" 문장(F-05)이 이미 있어 겹치고, AI가 숫자를 틀리거나 평가 표현을 쓸 위험이 있다. 아이디어 보관함 OpenRouter 후보 중 "자연어 → 필터 변환"을 채택했다.
- **AI의 역할:** 문장을 **정해진 필터 ID 목록**(1~20, 2026-11-13 F-14로 20번 추가)으로 바꾸기만 한다. 예: "배당 주는 회사 찾아줘" → 20번. 배당수익률을 숫자로 묻는 문장("배당수익률 3% 넘는 회사")은 해당 필터가 없으므로 **규칙 3**(필터에 없는 조건)으로 처리한다 (2026-11-13 사용자 확정). 숫자나 의견을 말하지 않는다. 실제 검색과 결과 표시는 스크리너가 한다.
- **위치:** 스크리너 화면 맨 위, 필터 버튼 위쪽.

**동작**

- **한 번에 한 문장.** 입력할 때마다 새로 찾는다. 앞 입력을 이어받지 않는다 ("거기서 빚 조건은 빼줘" 같은 이어 말하기는 초기에는 없음). 고치고 싶으면 사용자가 필터 버튼을 직접 눌러 빼거나 더한다.
- 동작 규칙 (안내 문구는 2026-11-16 확정, 아래 "화면 문구"):
  1. **AI가 고른 필터를 숨기지 않는다.** 입력 뒤 필터 버튼이 눌린 상태로 바뀌고 "이 조건으로 찾았어: 부채비율이 100% 이하인 회사, 매출이 2년 연속 늘어난 회사"라고 보여준다.
  2. **스크리너 규칙을 그대로 따른다** (필터 최대 3개, 부딪히는 필터는 같이 고르지 않음). 문장이 부딪히는 두 조건(F-03 "부딪히는 필터")을 담으면 "'{A}'와 '{B}'를 함께 만족하는 회사는 없어. 하나를 빼고 다시 적어 줘."라고 알린다 (2026-11-16 확정).
     - **부딪히는 조건이 들어오면 필터를 아무것도 적용하지 않는다** (2026-11-16, 사용자 "확정"). 어느 쪽을 원했는지 서비스가 고르지 않는다.
     - **필터를 4개 이상 고른 경우 (2026-11-16, 사용자 A안):** **문장에 나온 순서대로 앞의 3개만 적용하고 알린다** ("필터는 3개까지라 앞의 3개만 골랐어: {…}. 나머지는 버튼에서 바꿔 골라 줘."). 사용자가 필터 버튼으로 바꿔 고를 수 있다. 채택하지 않은 안: B "아무것도 적용하지 않고 3개 이하로 다시 입력하게 함".
     - **13번과 14번을 같이 고른 경우 (2026-11-16, 설계 에이전트 기본값, 사용자에게 알림):** F-07 포함 관계 규칙(13 ⊃ 14)에 맞춰 **더 좁은 14번만 남긴다.**
     - **금융회사:** 쓸 수 없는 필터가 고른 목록에 있으면 F-07과 같은 빠짐 안내가 나온다 ([금융회사 처리 한눈에](#금융회사-처리-한눈에)).
  3. **필터에 없는 조건은 없다고 알린다.** 예: "배당수익률 조건은 지원하지 않아." + 나머지 조건만 적용. 예: "매출 늘고 배당수익률 3% 넘는 회사" → "배당수익률 조건은 지원하지 않아."라고 알리고 "매출이 2년 연속 늘어난 회사"(1번)만 적용.
     - **고정 종류 목록 (2026-11-16, 사용자 A안):** "AI는 필터 ID만 고르고 말하지 않는다" 원칙을 지키려고, **지원하지 않는 조건도 정해진 종류 코드에서만 고르게 한다.** AI는 필터 ID + 종류 코드를 돌려주고, 화면에는 코드별 고정 문구가 나온다. AI 출력이 정해진 ID·코드 밖이면 버린다 (기존 검사 방침과 같음). 목록은 나중에 늘릴 수 있다.

       | 종류 | 고정 문구 |
       | --- | --- |
       | 업종 | 업종 조건은 지원하지 않아. 업종은 '업종으로 둘러보기'에서 볼 수 있어. |
       | 배당수익률 | 배당수익률 조건은 지원하지 않아. |
       | 주가·PER·PBR | 주가 조건은 지원하지 않아. |
       | 그 밖 | 문장 속 일부 조건은 지원하지 않아서 빼고 찾았어. |

       - 채택하지 않은 안: B "어떤 조건이든 한 문구('문장 속 일부 조건은 지원하지 않아서 빼고 찾았어.')".
     - **고를 필터가 하나도 없고 지원하지 않는 조건만 있으면** 규칙 3 문구만 보여주고 필터는 적용하지 않는다 (2026-11-16, 사용자 "확정").
     - **업종을 묻는 문장도 규칙 3이다** (2026-11-14 F-15, 사용자 확정). 예: "반도체 회사 찾아줘" → "업종 조건은 지원하지 않아. 업종은 '업종으로 둘러보기'에서 볼 수 있어." (2026-11-16 확정, 위 "업종" 종류).
  4. **조건이 아닌 말에는 답하지 않는다.** 예: "삼성전자 살까?" → "조건으로 바꿀 수 없는 질문이야. 예: 부채비율이 낮고 매출이 늘어난 회사" (2026-11-12 사용자 확인).
  5. 입력창 아래에 **예시 문장 3개**를 보여준다 (눌러서 바로 실행). **예시 문장 확정 (2026-11-14 사용자 확정, A안):**

     | 예시 문장 | 고르는 필터 |
     | --- | --- |
     | 빚이 적고 매출이 늘어나는 회사 | 13번 "부채비율이 100% 이하인 회사" + 1번 "매출이 2년 연속 늘어난 회사" |
     | 적자에서 흑자로 돌아선 회사 | 8번 "영업이익이 흑자로 돌아선 회사" |
     | 꾸준히 배당하는 회사 | 20번 "3년 내내 현금배당한 회사" |

     - 이유: 초보자가 쓸 법한 일상 말투라 "문장으로 찾기"를 바로 보여준다. 빚·이익·배당 세 주제를 고르게 보여준다. 규칙 4 안내 문구의 예시("부채비율이 낮고 매출이 늘어난 회사")와 이어진다. 세 문장 모두 부딪히는 조합이 아니고 필터 3개 이하다.
     - 예시 위 안내 문구: "이렇게 적어 봐" (2026-11-16 확정).
     - 채택하지 않은 안: B "필터 문구에 가까운 말투 3개" (필터 버튼과 거의 같아 챗봇 의미가 약함), C "A에서 2개만" (이익 주제가 빠짐).
  6. **AI가 응답하지 않으면**(한도 초과·오류) 입력창만 숨기고 "지금은 문장으로 찾기를 쓸 수 없어. 아래 버튼으로 골라 줘."(2026-11-16 확정)라고 안내한다. 필터 버튼은 그대로 쓴다.

### 사용자 기능 (F-11~F-13) 공통

- **개발 순서:** 기본 기능과 기능 목록의 "이후" 단계를 모두 끝낸 뒤 **맨 마지막 확장 기능**으로 붙인다 (2026-11-11 결정). 그 전까지 서비스는 로그인 없이 모두 쓸 수 있다.
- **전체 흐름:**
  1. 비로그인 사용자도 검색(F-01)·그래프(F-02)·필터(F-03, F-07)를 그대로 쓴다.
  2. 종목 상세에서 "추적하기"를 누르면 로그인(F-11)으로 안내한다.
  3. 로그인하면 그 종목이 추적 목록에 들어가고(F-12), 마이페이지에서 모아 본다.
  4. 수집 배치(F-04)가 데이터를 갱신하면서 추적 종목의 변화를 찾아 알림을 만든다(F-13). 웹 화면 알림으로 쌓고, 이메일 수신을 켠 사용자에게는 메일도 보낸다.
- **원칙:** 마이페이지·알림 문구도 매수·매도 추천, "좋은 회사", 전망 표현을 쓰지 않는다. 사실과 변화만 쓴다. 메일 하단에도 출처와 "투자 판단의 책임은 본인에게 있다" 고지를 넣는다.
- **개인정보:** 이메일 주소만 수집한다. 가입 화면에 수집 항목·목적(로그인, 알림 발송)을 안내하고, 마이페이지에서 탈퇴(계정·추적 목록·알림 삭제)할 수 있게 한다.

### F-11 로그인

- **목표:** 추적 종목과 알림을 사용자별로 저장하기 위해 로그인을 붙인다.
- **방식:** **이메일 매직링크** (2026-11-11 결정). Supabase Auth를 쓴다. 이메일을 입력하면 로그인 링크가 오고, 링크를 누르면 로그인된다. 비밀번호를 저장·관리하지 않는다.
- **화면:** 상단 메뉴에 "로그인" 버튼 → 이메일 입력 → "메일함을 확인하세요" 안내 → 링크 클릭 → 원래 보던 화면으로 돌아옴. 로그인 후에는 메뉴에 "마이페이지", "로그아웃".
- **예외 처리:** 링크 만료 시 다시 보내기 버튼. 메일이 안 오면 스팸함 확인 안내.
- **토론 결과 (2026-11-12):** 변경 없음. 서비스 쪽에서 더 정할 것이 없고, 남은 할 일은 개발 쪽이다.

**배당수익률 계산 주가 시점 (2026-11-16 확인, 기능 설계 세션)**

- 공식 작성기준 원문은 찾지 못했고, 실제 사업보고서 주석 1건으로 확인했다: 현대건설기계 2021 사업보고서(정정, 2022-03-15) 배당에 관한 사항 "※ 현금배당수익률(%) = 1주당 현금배당금/주주명부폐쇄일 2 매매거래일전부터 과거 1주일간의 거래소 시장에서 형성된 최종주가의 산술평균가격" (예: 1,200원 ÷ 40,210원 = 2.98%). 출처 https://kind.krx.co.kr/external/2022/03/15/001524/20220315003623/11011.htm
- 검색 결과로는 "배당기준일 전전거래일부터 과거 1주일"처럼 회사마다 기준일 표기가 조금 다르다 (검색 요약 기준, 원문 미확인). 공통점: 배당받을 주주를 정하는 날 무렵 1주일 평균 주가. 그래서 **문구에 정확한 날짜는 쓰지 않는다.**

**기본값 (설계 세션이 잡고 사용자가 "이대로 확정"으로 승인, 2026-11-13)**

- 표의 연도는 F-02 그래프와 같은 연도를 쓴다.
- 20번 필터로 걸린 회사는 스크리너 결과 줄에 3년 주당 배당금을 근거 값으로 보여준다 (F-07 근거 값 열 규칙).
- 20번과 부딪히는 필터 짝은 없다.
- DART가 `013`을 주거나 사업보고서가 없으면 "이 회사의 배당 정보가 없어."
- 3개년이 다 없는 회사는 있는 연도만 표에 보여주고, 20번 필터 대상에서 빠진다.
- F-12 추적 종목 카드와 F-13 알림에는 배당을 넣지 않는다.
- "주당 배당금", "배당수익률"에 뜻풀이 툴팁을 단다.

### F-15 업종으로 둘러보기

- **목표:** 회사 이름을 몰라도 업종에서 출발해 회사를 찾게 한다. 검색창(F-01)은 이름을 알아야 쓸 수 있는데, 초보자가 아는 상장사는 몇 개뿐이다. 어떤 회사도 먼저 내세우지 않는다.
- **채택:** 제안 N-4에서 채택 (2026-11-14, 사용자 확정). 기능 설계 세션이 사용자와 질문 7개로 정함. 제안 원문은 2026-11-17 정리로 `docs/제안.md`에서 지웠다 (이 절이 설계 본문).
- **입력 / 출력:** 대분류 → 중분류 선택 → 그 업종의 회사 목록 (종목명·종목코드·시장 + 시가총액) → 종목을 누르면 종목 화면
- **사용 데이터:** DART 기업개황 업종 코드 `induty_code` 앞 두 자리(중분류, F-08과 같은 묶음), 주식시세정보 시가총액 `mrktTotAmt`(F-09와 같은 값), 한국표준산업분류 대분류·중분류 이름표. **추가 API 호출은 없다.**

**기본값 (설계 세션이 잡고 사용자가 "확정"으로 승인, 2026-11-14)**

- **대상 회사:** F-01 검색 대상과 같다 (코넥스·스팩 제외, 약 2,570개). 외국회사(`crno`가 `0000000000000`)는 재무를 지원하지 않으므로 목록에 넣지 않는다.
- **업종 코드가 없는 회사:** 둘러보기 목록에 나오지 않는다. 검색으로는 찾을 수 있다. (DART 표본에서는 그런 회사가 없었다.)
- **회사가 0개인 업종:** 목록에 보여주지 않는다. 회사가 1~2개뿐인 업종은 그대로 보여준다 (F-08의 "최소 회사 수"는 가운데 값 계산용이라 여기에 적용하지 않는다).
- **업종 순서:** 대분류·중분류 모두 분류 번호순. 회사 수 순은 순위표처럼 보여서 쓰지 않는다.
- **한 번에 보여줄 개수:** F-07과 같은 선택 상자 (기본 10개, **선택지 10 / 20 / 50개 + 목록 아래 페이지 번호**, 2026-11-15 F-07과 함께 정함). 목록 위에 "이 업종 회사 123개"처럼 개수를 표시한다. 회사가 몰린 업종도 페이지 넘김으로 처리해 별도 규칙을 두지 않는다 (2026-11-15).
- **시가총액:** F-09와 같이 보통주 기준이고, 목록 위에 주가 기준일을 적는다. 시가총액이 없는 회사는 칸을 "-"로 두고 시가총액순 정렬에서 맨 뒤로 보낸다.
- **12월 결산이 아닌 회사:** F-08 규칙대로 종목명 옆에 "3월 결산"처럼 표시한다.
- **스크리너와 조합:** 업종 안에서 필터를 거는 기능은 넣지 않는다 (개선안으로 아이디어 보관함).
- **챗봇(F-10):** 업종을 묻는 문장("반도체 회사 찾아줘")은 지원하지 않는다. F-10 규칙 3("업종" 종류)으로 처리하고 "업종 조건은 지원하지 않아. 업종은 '업종으로 둘러보기'에서 볼 수 있어."를 보여준다 (2026-11-16 확정).
- **넣지 않는 것:** "인기 종목", "많이 본 종목", 업종별 등락률·평균 수익률. 추천이나 매매 신호로 읽힌다.
- **수집:** 추가 호출 없음. F-04가 저장한 업종 코드와 시가총액을 그대로 쓴다.
